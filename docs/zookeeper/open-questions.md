## ZK-Q-001：alive 临时节点是新增机制还是版本差异

- **原问题**：hosp-006 有 alive 临时节点，hosp-007 没有。alive 是程序版本升级后新增的心跳机制，还是 hosp-007 因异常而无法创建 alive？
- **观察事实**：hosp-006 alive=临时节点（ephemeralOwner≠0），hosp-007 无 alive 节点
- **确认回答**：`/bsoft-cdc/clients` 下每个直接子节点代表一个独立进程。进程启动时向 ZK 注册 `alive` 临时节点。`alive` 存在表示进程正在运行，`alive` 不存在表示进程未运行。
- **最终状态**：已确认
- **最终结论**：
  - 在线 = alive 临时节点存在
  - 离线 = alive 临时节点不存在
- **对后续开发的影响**：在线状态判断统一使用 alive 节点是否存在，不依赖其他字段

## ZK-Q-005：scn 节点的生命周期

- **原问题**：scn 数据何时写入？是否在增量阶段才会出现？
- **观察事实**：上一轮 scn 含 offset 值，本轮为空 JSON `{}`
- **确认回答**：快照阶段 SCN 为空，进入增量阶段后写入。正确格式为 `{"scn":"31120290432","updateTime":"2026-07-16 16:00:04"}`。
- **最终状态**：已确认
- **最终结论**：
  - 快照阶段 SCN 可为空
  - 进入增量阶段后写入 SCN
  - 统一使用字段名 `scn`，不再使用 `offset`
  - 页面和 API 必须允许 SCN 为空
- **对后续开发的影响**：SCN 字段使用 `scn` 名，允许 null/空值
