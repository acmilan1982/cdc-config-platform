# 在线状态判断规则

> 分析时间：2026-07-17 16:39 CST
> 更新日期：2026-07-17（根据项目负责人确认回答固化）
> 分类：项目负责人已确认

## 一、正式规则

### 客户端在线状态（项目负责人已确认）

```text
客户端在线  = /bsoft-cdc/clients/{client}/alive 临时节点存在
客户端离线  = /bsoft-cdc/clients/{client}/alive 临时节点不存在
```

**依据**：`alive` 是 ZooKeeper 临时（ephemeral）节点。进程启动时创建，会话断开时 ZK 自动删除。这是 ZK 原生会话生命周期机制。

### 不依赖以下依据

| 不可依赖 | 原因 |
|----------|------|
| alive 的 updateTime | alive 不需要周期性更新，依赖的是临时节点机制本身 |
| alive 的 mtime | 同上 |
| status.code | 仅反映应用层状态，不反映 ZK 会话是否在线 |
| jobs 是否存在 | jobs 可以为空（进程启动后很快关闭的情况） |
| 其他永久节点是否存在 | 全部为永久节点，不随会话删除 |

## 二、alive 临时节点（核心机制）

| 属性 | 值 |
|------|-----|
| 节点类型 | 临时节点（ephemeralOwner ≠ 0x0） |
| 生命周期 | 随客户端 ZK 会话创建和销毁 |
| 是否周期性更新 | **否**，依赖会话存活而非数据更新 |
| 数据内容 | clientId, ip, pid, instanceId, startTime, updateTime |
| updateTime 用途 | 记录创建时间，不用于在线判断 |

### 实际观察

| 客户端 | alive 存在 | status.code | 在线判断 |
|--------|-----------|-------------|----------|
| hosp-006 | 是 | 1002（正常） | **在线** |
| hosp-007 | 否 | 9001（异常） | **离线** |

## 三、在线判断决策树

```text
/alive 节点是否存在？
├── 存在 → 在线（ZK 会话活跃）
│   └── status.code 展示应用层状态（1002/9001 等）
└── 不存在 → 离线（ZK 会话已断开）
    └── status 节点保留最后已知状态
```

## 四、status.code 展示

- 不需要掌握完整枚举值
- 仅读取并展示当前实际值
- 已观察到的值（1001/1002/1101/9001）仅为示例，不是完整列表
- 不将 code 映射为预设的中文枚举
- 可展示 status.description 作为状态说明

## 五、监控范围

| 范围 | 状态 |
|------|------|
| `/bsoft-cdc/clients` | **本期监控对象** |
| `/bsoft-cdc/servers` | 暂不处理（项目负责人确认） |

## 六、时间字段

| 字段 | 格式 | 时区 | 用途 |
|------|------|------|------|
| updateTime | yyyy-MM-dd HH:mm:ss | CST | 各节点最后更新时间（秒级精度），**不用于在线判断** |
| ctime（ZK stat） | EEE MMM dd HH:mm:ss zzz yyyy | CST | 节点创建时间 |
| mtime（ZK stat） | 同上 | CST | 节点最后修改时间，**不用于在线判断** |
