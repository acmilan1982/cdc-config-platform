## 二、可确认的在线判断依据

### 1. alive 临时节点是否存在（最可靠）

`alive` 为临时节点，客户端断连时 ZK 自动删除。

```text
IF alive 节点存在 THEN 客户端 ZK 会话在线
IF alive 节点不存在 THEN 客户端 ZK 会话已断开
```

**依据**：ZK 临时节点的生命周期与会话绑定，这是 ZK 原生机制，无需依赖应用层逻辑。

## 三、不可靠的在线判断依据

### 1. 节点是否存在（alive 除外）

除 `alive` 外的所有节点都是永久节点，hosp-007 虽异常但节点仍存在。

### 2. ZK ctime

节点创建时间仅表示首次注册时间。hosp-006 今天重新创建（ctime=2026-07-17），hosp-007 也是今天创建。

### 3. jobs 子节点数量

hosp-007 的 jobs 为空，不代表离线——可能仅表示该探针暂未分配采集任务。

## 四、推荐的在线判断规则

### 规则 1：alive 临时节点判断（最优先）

```text
在线 = alive 节点存在（ephemeralOwner ≠ 0x0）
离线 = alive 节点不存在
```

**可信度**：确认（基于 ZK 原生临时节点机制）

### 规则 2：status.code 辅助判断

```text
IF status.code 以 "1" 开头 THEN 应用层正常
IF status.code 以 "9" 开头 THEN 应用层异常
```

**可信度**：高（需完整枚举值确认）

### 规则 3：updateTime 超时判断（备用）

```text
IF alive 节点不存在 AND (当前时间 - status.updateTime) > 阈值 THEN 疑似离线
```

阈值建议 5-10 分钟。此规则用于判断无 alive 节点的旧版本客户端。
