> 本文档只做**模板基线级设计**，**不**锁定最终实现形态。
> 最终实现方案（CSS 预设 / CSS 变量 / Vue 轻包装 / 组合方式）必须由**后续独立**
> `SHARED_COMPONENT_DESIGN` 类任务决定，本任务**不得**提前定案。
> 本文档中的所有模板规则均为 `LIST_TABLE_TEMPLATE_DRAFT`（**未批准**），
> 所有实现方案均为 `LIST_TABLE_PROPOSED_NOT_IMPLEMENTED`（**未实现**）。

## 1. 模板职责

`LIST_TABLE_TEMPLATE_DRAFT` —— 本模板负责**主列表表格的基础视觉与结构纪律**：

1. **表头纪律**：表头背景、表头文字的字号 / 字重 / 颜色 / 字距、表头单元格上下内边距；
2. **正文纪律**：正文基础字号 / 颜色、正文单元格上下内边距；
3. **边框与分隔**：表格边框策略与分隔线颜色；
4. **间距纪律**：表头与正文的纵向留白节奏；
5. **行高策略**：默认行高与内容驱动的自适应行高的**边界**；
6. **长文本与扩展边界**：单行长文本省略策略、Tooltip 是否由字段语义**决定**；
7. **作用域纪律**：显式启用、作用域隔离、对未启用页面零样式泄漏；
8. **可覆盖纪律**：公共默认值可被 Feature **局部覆盖**，且覆盖方式受控、可回滚。

`LIST_TABLE_TEMPLATE_DRAFT` —— 本模板**不**负责：

- 页面壳层、查询区、结果区、刷新工具栏与请求交互（属 `query-list-page-template`）；
- 业务列定义、列宽、数据模型与状态语义（属 Feature，见 §2）；
- 任何需要“业务含义”才能决定的语义（见 §7）。

## 2. Feature 保留职责

`LIST_TABLE_TEMPLATE_DRAFT` —— 以下**必须**由业务 Feature 保留，公共层**不得**为其提供默认值：

| 保留项 | 说明 |
| --- | --- |
| 业务列 | 列的名称、数量、顺序；列的 `prop` / 渲染方式 |
| 列宽 | 每列 `width` / `min-width`；表格整体 `min-width`（为列宽之和） |
| 数据 | 数据来源、请求参数、分页与最大返回条数 |
| 状态语义 | 状态标签的配色、文案与判定规则 |
| 行操作 | 行级操作列、操作按钮、权限与禁用规则 |
| 选择 | 是否需要多选、选中态样式与批量操作 |
| Tooltip | 哪些字段需要 Tooltip、内容上限、触发延迟 |
| 分页 | 是否分页、分页控件形态与页大小 |
| 空态 | 空态文案与层级（单行 / 两级） |
| Loading | 是否 `v-loading`、以及 loading 文案 |
| 错误处理 | 请求失败提示文案与重试策略 |

`LIST_TABLE_TEMPLATE_DRAFT` —— 本模板**只**收敛“表格长什么样”的共性纪律，
**不**收敛“表格装什么、怎么交互”。

## 3. 显式启用与作用域隔离

`LIST_TABLE_TEMPLATE_DRAFT`：

1. **显式启用**：模板能力必须由页面**显式**启用（例如显式应用预设类 / 显式导入包装 /
   显式声明令牌），**不得**通过全局样式或全局选择器隐式作用到所有 `el-table`；
2. **零全局泄漏**：公共层**不得**新增全局样式块，**不得**在 `:root` / `body` 定义模板令牌；
3. **作用域限定**：所有深度选择器必须由**本模板自己的根类**限定，
   **不得**出现不带模板前缀的裸 `:deep(...)`；
4. **不选择既有业务前缀**：模板类 **不得**引用、选择或覆盖既有业务前缀
   （`.data-table`、`.dss-*`、`.toff-*`、`.cc-table`、`.config-table` 等）；
5. **未启用页面零变化**：未启用模板的页面，其计算样式必须与启用前**逐值相同**，
   模板令牌在其上下文中应**不可解析**。

> 边界（与 qlpt 的既有约定一致）：`query-list-page-template` 已批准的详细设计
> 明确把 `el-table` 内部结构类（`el-table__cell` 内边距、表头 `.cell` 排版）**留在 Feature**。
> 本模板**新开一层**来承载这部分纪律，**不**推翻该约定：
> 它仍由 Feature 显式选择是否套用，而不是由 qlpt 或公共层自动注入。

## 4. 公共默认值与 Feature 局部覆盖

`LIST_TABLE_TEMPLATE_DRAFT`：

- 模板提供**公共默认值**（表头 / 正文 / 边框 / 间距的默认纪律）；
- Feature 可在**自身作用域内局部覆盖**默认值（业务确有差异时）；
- 覆盖必须**收敛在本页面的表格根类内**，**不得**泄漏到其他页面；
- 覆盖必须**可枚举、可回滚**：覆盖点应是有限、命名清晰的；
- 模板**不得**为业务语义预设默认值（见 §7），因此“覆盖”只发生在**视觉纪律**层面，
  不发生在**业务语义**层面。

`LIST_TABLE_PROPOSED_NOT_IMPLEMENTED` —— 覆盖的**具体技术形态**
（是覆盖 CSS 变量、是传入 Props、还是 Feature 自带 scoped 规则）留待详细设计决定。

## 5. 行高策略

`LIST_TABLE_TEMPLATE_DRAFT`：

1. **默认行高**：模板对主列表给出**内容驱动**的默认行为，
   即不强制固定行高，让行高随单元格内容自然撑开；
2. **内容驱动自适应**：当单元格包含**多行内容、复杂标签或被包换的文本**时，
   行高应**自适应增高**，**不得**被公共规则压平或裁切；
3. **固定行高**：固定行高是**Feature 决定**的例外，
   仅适用于“该页面每一行内容高度可预期且需要严格对齐”的场景；
   采用固定行高时，Feature 必须**自行**声明并承担“复杂内容被压平”的风险；
4. **模板不得**在公共层强制固定行高，也**不得**在公共层禁止固定行高——
   它只规定**默认行为**与**允许例外的条件**。

## 6. 长文本、省略与 Tooltip

`LIST_TABLE_TEMPLATE_DRAFT`：

1. **单行省略**：对需要保持单行的长文本字段，采用**单行省略**
   （`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`）的纪律；
2. **Tooltip 由字段语义决定**：是否启用 Tooltip、使用哪种 Tooltip 机制、
   延迟多少毫秒，**由字段的业务语义决定**，**不由**视觉模板统一强制；
3. **模板不内置业务内容**：模板**不得**内置任何业务提示文案或字段清单；
4. **多行内容优先于省略**：当字段语义要求展示完整多行内容时，
   应放弃单行省略与压平，改用自适应行高（见 §5）；
5. **单实例 Tooltip 的归属**：若未来采用“单实例 Tooltip”机制，
   其**机制**可否复用必须由详细设计评估；
   但**哪些字段需要 Tooltip**始终属 Feature。

## 7. 不得未经评估抽成公共业务语义的内容

`LIST_TABLE_TEMPLATE_DRAFT` —— 以下**不得**未经独立评估就抽象为公共业务语义：

- **选中态**（如某页面 `#ecf5ff` 底色 + `inset 3px 0 0` 左侧条）；
- **异常态**（如某页面的警告色行底色）；
- **hover 态**的配色；
- **状态标签**的配色与语义（成功 / 警告 / 危险 / 信息）；
- **ID 强调**（等宽字体 + 加粗 + 数字对齐的特殊强调）；
- **序号列**的特殊排版（等宽数字、次级灰色）；
- **“停用 / 异常”标记**的 pill 几何与配色；
- **“更多”操作**的展开行为与呈现。

`LIST_TABLE_TEMPLATE_DRAFT` —— 以上内容在参考实现中**存在**，
但它们是**某个 Feature 的业务语义**（比如“停用”“异常”是数据源管理特有的状态），
**不得**因为“看起来可复用”就提升为公共规范。
如未来确需复用，必须由**独立任务**逐项评估其**语义是否普适**、
**是否会造成跨页面语义污染**，并**独立授权**。

## 8. 候选实现方案对比（不定案）

`LIST_TABLE_PROPOSED_NOT_IMPLEMENTED` —— 以下为候选方案，**均未实现**，
且**本轮不得**选择其一作为最终方案。最终方案由后续详细设计任务决定。

### 8.1 显式 CSS 预设（纯类名）

| 维度 | 评估 |
| --- | --- |
| 形态 | 提供一个（或一组）显式类名，Feature 在**自己的表格根类**上并列声明 |
| 优点 | 无组件开销；与现有 `:deep(.el-table__cell)` 写法最接近；迁移成本低 |
| 缺点 | 规则的“契约”较难表达（跨文件、无类型）；容易退化为复制粘贴 |
| 泄漏风险 | 中——若预设类写在全局 `<style>` 且优先级高，可能影响未启用页面 |
| 测试方式 | 计算样式逐路由断言；负向控制（把预设写全局/写 `:root` 时应非零退出） |
| 回滚方式 | 移除类名即可，无运行时状态 |

### 8.2 CSS 变量（令牌）

| 维度 | 评估 |
| --- | --- |
| 形态 | 在表格根元素上定义 `--lt-*` 令牌，业务规则消费令牌；Feature 局部覆盖令牌 |
| 优点 | 覆盖粒度细、可枚举；覆盖不产生选择器冲突；天然限定在声明元素的子树内 |
| 缺点 | 需要 Element Plus 深度选择器消费令牌，仍需 scoped 包裹 |
| 泄漏风险 | 低——令牌定义在组件根元素，**不**定义在 `:root` / `body` |
| 测试方式 | 未启用页面上的 `--lt-*` 应**不可解析**；逐路由计算样式断言 |
| 回滚方式 | 删除令牌定义与消费规则 |

### 8.3 Vue 轻包装组件

| 维度 | 评估 |
| --- | --- |
| 形态 | 一个薄包装组件，透传 `el-table` 的默认值（如 `:cell-style` / 类名） |
| 优点 | 契约集中在组件属性上，可类型化；显式启用语义最强 |
| 缺点 | 可能“吞”掉 `el-table` 的 slot / 事件，造成与 qlpt 相同的老问题（超级组件 + 薄包装之争）；增加一层间接 |
| 泄漏风险 | 低——样式随组件 scoped |
| 测试方式 | 组件契约测试 + 几何等价断言（接入前后计算样式逐值相同） |
| 回滚方式 | 换回原生 `el-table` 并移除包装 import |

### 8.4 组合方式

| 维度 | 评估 |
| --- | --- |
| 形态 | “预设 CSS 类” + “有限令牌覆盖”，不引入组件 |
| 优点 | 兼顾“显式启用”与“细粒度覆盖”；无组件间接；与现有写法兼容 |
| 缺点 | 契约仍无类型；需要纪律约束覆盖点数量 |
| 泄漏风险 | 低至中——取决于是否避免全局作用域 |
| 测试方式 | 同 §8.2，并额外断言“覆盖点数量有限且命名清晰” |
| 回滚方式 | 移除类名与令牌 |

### 8.5 对比小结

`LIST_TABLE_PROPOSED_NOT_IMPLEMENTED`：

- **不引入组件**的方案（8.1 / 8.2 / 8.4）泄漏风险更可控、迁移成本更低，
  但契约可表达性较弱；
- **引入组件**的方案（8.3）契约最强，但与 qlpt 已评估的
  “不做超级组件、不做薄包装”结论存在张力，需重新论证；
- 无论采用哪种，**必须**满足 §3 的显式启用与零泄漏要求；
- **本文档不对任一方案定案**。最终方案由后续 `SHARED_COMPONENT_DESIGN` 类任务
  基于本轮草案与真实源码决定。

- 不修改 `frontend/**`、`backend/**`、测试代码、配置、依赖或锁文件；
- 不修改数据源管理页面或任何其他页面；
- 不执行测试、构建、浏览器或服务操作；
- 不把草案写成已批准，不把候选方案写成已实现；
