## 5. 两级状态体系的颜色和样式

页面采用**两级状态**，不在所有位置直接展示同一套状态。

### 5.1 Job 当前状态（2 种，用于主页面列表和详情页顶部）

| 状态 | 中文 | 标签样式 | 判定规则 |
|------|------|----------|----------|
| NORMAL | 正常 | 绿色文字 #67C23A + 浅绿色背景 #f0f9eb | 无故障记录，或最近一次故障已闭环 |
| RECOVERING | 恢复中 | 红色文字 #F56C6C + 浅红色背景 #fef0f0 | 最近一次故障尚未闭环 |

**重要**："正常"仅表示当前失败恢复记录中不存在未闭环故障，不代表已验证物理 Job 正在运行。无运行依据时需通过悬停提示解释。

等待重启、重启中、恢复失败、流程异常 → 在主页面和详情页顶部统一显示为"恢复中"。

### 5.2 故障过程状态（5 种，用于故障汇总和历史列表）

| 状态 | 中文 | 标签样式 | 说明 |
|------|------|----------|------|
| RECOVERED | 已恢复 | 绿色文字 #67C23A + 浅绿色背景 #f0f9eb | 该次故障过程已闭环 |
| WAITING_RESTART | 等待重启 | 红色文字 #F56C6C + 浅红色背景 #fef0f0 | 已进入等待重启阶段 |
| RESTARTING | 重启中 | 红色文字 #F56C6C + 浅红色背景 #fef0f0 | 已开始重启但尚未稳定恢复 |
| RECOVERY_FAILED | 恢复失败 | 红色文字 #F56C6C + 浅红色背景 #fef0f0 | 恢复动作失败，故障尚未闭环 |
| ABNORMAL | 流程异常 | 红色文字 #F56C6C + 浅红色背景 #fef0f0 | 存在分叉、多前驱、循环、断链或关键时间异常 |

### 5.3 两级状态映射

| 故障过程状态 | Job 当前状态 |
|-------------|-------------|
| 已恢复 | 正常 |
| 等待重启 | 恢复中 |
| 重启中 | 恢复中 |
| 恢复失败 | 恢复中 |
| 流程异常 | 恢复中 |
| 无故障记录 | 正常 |

### 5.4 颜色规范

- 绿色：`#67C23A`（对应 Element Plus `--el-color-success`）
- 红色：`#F56C6C`（对应 Element Plus `--el-color-danger`）
- 标签背景：浅绿 `#f0f9eb` / 浅红 `#fef0f0`
- 不增加状态圆点
- 不使用大面积彩色背景

## 6. 客户端分组折叠规则

| 规则项 | 定义 |
|--------|------|
| 折叠组件 | 使用 Element Plus `el-collapse` 或等价自定义折叠面板 |
| 默认展开 | 异常数量 > 0：首次进入页面时默认**展开** |
| 默认折叠 | 异常数量 = 0：首次进入页面时默认**折叠** |
| 用户手动选择保持 | 用户手动展开或折叠后，本次页面访问期间保持用户选择 |
| 自动刷新不重置 | 自动刷新**不得**重置用户的展开/折叠状态 |
| 展开/折叠触发 | 点击客户端标题栏整行 |
| 折叠图标 | 左侧 `▶` 箭头，展开时旋转 90° |
| 过渡动画 | 使用 CSS transition 平滑展开/折叠，约 0.3s |
| 页面返回后 | 返回主页面后恢复客户端展开状态（与滚动位置、刷新周期一起恢复） |
| 无障碍 | 支持键盘 Enter/Space 触发折叠 |

## 8. 事件卡片默认展开规则

事件卡片按**时间倒序**排列（事件 3 → 事件 2 → 事件 1，从最新到最早）。

| 场景 | 默认展开 | 说明 |
|------|----------|------|
| 已闭环故障 | 展开**最后一个**事件（链尾） | 最后一个事件包含 STABLE_CHECK_PASSED，是关键闭环节点 |
| 未闭环故障 | 展开**当前正在处理的事件**（链尾） | 当前事件是运维关注焦点 |
| 存在异常事件 | 异常事件默认展开 | 让异常链可见 |
| 其他事件 | 默认折叠 | -- |
| 单事件故障 | 始终展开 | -- |
| 用户手动展开后 | 保持用户操作状态，不得因 CLOB 懒加载而改变 | 基于 eventId 集合记录 |
| 最终成功节点 | 可显示"故障恢复闭环" | 不增加"首次失败"/"最终恢复"卡片标签 |

## 9. 时间线颜色与布局

### 9.1 时间线颜色规则

| 类型 | 节点/边框颜色 | 适用场景 |
|------|-------------|----------|
| 普通处理 | 蓝色 `#409eff` | JOB_FAILURE_RECEIVED、RESTART_STARTED、NEW_JOB_SUBMIT_SUCCEEDED |
| 等待/计划 | 橙色 `#e6a23c` | RESTART_SCHEDULED |
| 成功闭环 | 绿色 `#67C23A` + 浅绿填充 `#f0f9eb` | STABLE_CHECK_PASSED |
| 失败/异常 | 红色 `#F56C6C` | NEW_JOB_SUBMIT_FAILED、流程异常 |
| 辅助信息 | 灰色 `#909399` | 补充说明文本 |

不增加独立颜色图例，每个节点必须同时有清楚文字说明。

### 9.2 紧凑两层布局

时间线采用紧凑的两层结构，避免右侧大面积空白和页面过度拉长：

**第一行**（核心信息）：
- 时间（等宽字体 12px, #909399）
- 处理阶段（13px, font-weight: 500）
- 处理结果

**第二行**（补充信息，灰色 12px）：
- 尝试次数（ATTEMPT_NO）
- 退避时间（RESTART_DELAY_SECONDS）
- 计划重启时间（NEXT_RESTART_TIME）
- 新物理 Job ID（NEW_JOB_ID，蓝色等宽字体）

### 9.3 时间线关键视觉特征

- 左侧竖线：`2px solid #e4e7ed`
- 节点大小：`12px` 圆形，白色填充 + 对应颜色边框
- 节点位置：竖线中心
- 每条记录间距：`14px`（紧凑）
- CLOB 长文本默认最多显示 3 行，超出后"展开全文"

## 10. 长文本懒加载交互

| 项目 | 说明 |
|------|------|
| 涉及字段 | `CDC_JOB_FAILURE_EVENT.FAILURE_DETAIL` (CLOB)<br>`CDC_JOB_FAILURE_HANDLE_LOG.ERROR_DETAIL` (CLOB) |
| 默认展示 | 最多显示 **3 行**，超出后截断显示，末尾显示"展开全文"链接 |
| 懒加载入口 | 当 `failureDetailAvailable: true` 或 `errorDetailAvailable: true` 时，显示"展开全文"蓝色文字链接 |
| 点击行为 | 调用 API-5 懒加载完整内容；链接变为 loading 状态 |
| 加载成功 | 在事件卡片或时间线下方展开等宽字体文本区域，max-height: 300px 可滚动，提供"收起"和"复制全文"按钮 |
| 加载失败 | 仅影响长文本区域，不阻塞页面其他功能；显示"加载失败，点击重新加载" |
| 空 CLOB | 不显示入口 |
| 截断处理 | 超过 50000 字符时截断，显示 "内容过长（{N}字符），已截断至前 50000 字符" |
| 脱敏 | 后端自动脱敏 password/pwd/token/Authorization/CONNECTION_ID 等敏感信息；前端做二次脱敏校验 |

## 11. 空、加载、异常状态

### 11.1 主页面加载中

- 客户端分组区域显示骨架屏（skeleton）
- 每个骨架项包含：标题栏占位条 + 表格行占位（4-5 行灰色闪烁条）
- 骨架屏颜色：`#f2f2f2` → `#e6e6e6` 动画
- 不显示空状态图

### 11.2 主页面接口异常

- 保留旧数据不变（如有）
- 顶部显示 `el-alert type="warning"` 提示条："刷新失败，点击重试"
- 手动刷新按钮恢复可用
- 如首次加载即失败（无旧数据）：显示 `el-empty` 组件，"数据加载失败" + 重试按钮

### 11.3 活跃客户端为空

- `el-empty` 组件，插图 + "暂无活跃客户端"
- 描述文字："当前没有 FG_ACTIVE='1' 的 CDC 客户端"
- 不显示表格或分组

### 11.4 客户端存在但无逻辑 Job

- 客户端分组区域展开后显示 "暂无逻辑 Job"
- 使用 `el-empty` 的 small 变体或自定义空状态
- 保留客户端标题栏（客户端 ID、Job 总数=0、最近更新时间）

### 11.5 逻辑 Job 无故障记录

- 主页面：该 Job 行正常显示，状态=正常（绿色），当前 Job ID="--"，失败/恢复="--"，重启="--"
- "查看记录"按钮正常显示
- 详情页：汇总区域替换为 "暂无故障记录"（绿色空状态图标）
- 页签区域不显示（无故障则无页签切换必要）

### 11.6 详情页无故障记录

- 同 11.5 详情页处理
- `latestFault` 为 null，`hasFault: false`
- 展示空状态而非报错

### 11.7 长文本加载中

- 点击 "查看完整 FAILURE_DETAIL" 后，入口文字变为 "加载中..."
- 使用 `el-icon Loading` 旋转动画
- 加载完成后展开文本区域

### 11.8 长文本加载失败

- 展开区域显示 "加载失败"
- 提供 "重新加载" 按钮
- 不阻塞页面其他功能

### 11.9 异常链提示

采用**中等强度**提示，不使用大面积深红背景：

- 事件卡片标题栏右侧显示红色"异常链"标签
- 卡片左边框使用 3px 红色 `#F56C6C`
- 显示一行异常摘要文字
- 提供"查看异常详情"入口（展开后可查看完整异常说明）

异常类型及说明：

| 异常类型 | 出现位置 | 提示内容 |
|----------|----------|----------|
| 分叉 | 事件卡片 | "NEW_JOB_ID 匹配到 N 个后续事件（分叉），已取最早事件" |
| 循环 | 链图区域 + 汇总面板 | "检测到事件链循环，已在重复处截断" |
| 断链 | 汇总面板 + 物理 Job 演变链 | "事件链断裂，已作为独立故障处理"，断裂位置显示明确警告 |
| 重复 FAILED_JOB_ID | 事件卡片 | "检测到重复 FAILED_JOB_ID，已取最早事件" |
| 多前驱 | 汇总面板 | "检测到多前驱事件，可能存在数据关联歧义" |
| 处理记录缺失 | 事件卡片 | "处理记录缺失" |
| 时间字段缺失 | 汇总面板 | "部分时间字段缺失，已使用记录创建时间替代" |

**已删除**：黄色 ⚠ 警告图标（除异常链检测外不显示）。

### 与 CDC 节点状态页（ClientCard）的视觉差异

CDC 节点状态页采用了 glassmorphism 风格（backdrop-filter blur, 渐变背景, 圆角 16px）。本设计**明确不采用** glassmorphism 风格（043 已确认），理由如下：

1. 本页面信息密度更高（表格型数据），glassmorphism 的透明/模糊效果会降低文字可读性
2. 本页面以运维判断为核心场景，优先保证数据清晰度和扫描效率
3. 客户端分组使用轻量边框 + 浅灰标题栏，层级清晰但不抢夺注意力
4. 保持扁平边框风格，不增加厚重阴影
