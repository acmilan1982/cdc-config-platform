# ZooKeeper 节点监控核心需求

## 1. 功能目标

为 CDC 运维和开发人员提供 CDC 客户端进程在 ZooKeeper 中注册的运行状态、身份信息和采集进度的**只读查看**能力。

用户无需直接连接 ZooKeeper 或执行命令行操作，通过 Web 界面即可了解当前所有 CDC 客户端的在线状态和关键运行指标。

## 2. 使用场景

- 日常巡检：查看所有 CDC 客户端的在线状态，确认是否有客户端或采集任务离线；
- 进度跟踪：查看各采集任务当前发布的 SCN 值；
- 故障排查辅助：在故障发生时快速了解客户端在线状态和 SCN 情况，为后续故障分析提供基础信息。

## 3. 监控对象

### 3.1 监控范围

监控路径：`/bsoft-cdc/clients`，具体连接配置以项目级基线 [ENVIRONMENT.md](../../baseline/ENVIRONMENT.md) §3 为准。

### 3.2 监控层级

监控对象包括 CDC 客户端节点及其下属采集任务节点的运行状态信息。具体节点结构以 [docs/zookeeper/](../../zookeeper/) 下相关说明为准，不在此处固化为正式需求。

### 3.3 在线判定

客户端和采集任务均具有对应的 `alive` 临时节点，该节点是在线/离线判断的正式依据：

- 成功完成相应路径查询，确认 `alive` 临时节点存在 → 在线；
- 成功完成相应路径查询，确认 `alive` 临时节点不存在 → 离线；
- ZooKeeper 查询失败、连接异常、读取未完成或路径无法可靠解析 → 未知或读取异常。

普通身份、描述、SCN 或其他数据节点缺失，不得据此推断离线。在线判定规则的实现细节参考 [online-rules.md](../../zookeeper/online-rules.md)。

## 4. 数据来源

数据直接来源于 ZooKeeper，后端以只读方式访问 ZooKeeper。

不经过数据库业务表查询。ZooKeeper 连接配置（地址、根路径、超时等）以项目级环境基线 [ENVIRONMENT.md](../../baseline/ENVIRONMENT.md) §3 为准。

## 5. 核心信息范围

### 5.1 客户端信息

应展示 ZooKeeper 中实际存在且可可靠解析的客户端维度信息，包括但不限于：

- 客户端身份标识信息；
- 当前在线或运行状态信息；
- 所在主机或 IP 信息；
- 进程身份和生命周期信息；
- ZooKeeper 中已存在且能够可靠解释的其他客户端级监控信息。

最终展示字段以后续正式接口契约为准，当前实现中的具体字段不自动成为正式需求。

### 5.2 采集任务信息

每个客户端下的采集任务应展示 ZooKeeper 中可可靠读取的任务维度信息，包括但不限于：

- 任务标识和名称信息；
- 当前运行状态信息；
- SCN 采集进度信息（来自 ZooKeeper 持久化节点，按节点当前值展示）。

最终展示字段以后续正式接口契约为准，当前实现中的具体字段和 fallback 规则不自动成为正式需求。

### 5.3 SCN 采集进度

采集任务的采集进度以 SCN 表示，SCN 保存在 ZooKeeper 持久化节点中。本功能读取并展示节点中当前记录的 SCN 值，不写入或修改该节点。SCN 展示是现在和未来都必须提供的核心能力。

本功能按 ZooKeeper 节点当前值原样展示 SCN，不基于时间阈值或历史变化判断 SCN 是否过期、陈旧或停滞。

## 6. 数据操作边界

**本功能严格只读，禁止以下所有操作：**

- 创建 ZooKeeper 节点；
- 修改 ZooKeeper 节点数据；
- 删除 ZooKeeper 节点；
- 修改 ZooKeeper ACL 或集群配置；
- 向数据库写入、更新或删除任何业务数据；
- 启停或控制 CDC 客户端；
- 修改 CDC 客户端配置。

详见 [CLAUDE.md](../../../CLAUDE.md) §14（ZooKeeper 环境与操作规则）和 [DEVELOPMENT_RULES.md](../../baseline/DEVELOPMENT_RULES.md) §5。

## 7. 功能职责边界

### 7.1 与 Job 故障监控的边界

- **本功能**：展示 ZK 中的实时在线状态和 SCN 进度；
- **故障监控**（`job-failure-monitor`）：追踪数据库中的 Job 故障事件、处理记录和恢复过程。

本功能不处理故障事件分类、故障过程组装、故障链构建或故障恢复逻辑。

### 7.2 与大屏统计的边界

- **本功能**：展示 ZK 节点级运行信息；
- **大屏统计**（`large-screen`）：基于数据库日志表的增量统计聚合和可视化。

本功能不涉及数据库日志读取、统计计算或图表渲染。

### 7.3 与配置管理的边界

- **本功能**：只读查看 ZK 中已注册的客户端和任务状态；
- **配置管理**：对数据源、客户端、订阅等配置数据进行 CRUD 操作。

本功能不提供配置的增删改能力。

## 8. 异常与边界原则

### 8.1 ZooKeeper 不可访问

当 ZooKeeper 连接失败时，应向用户报告连接状态异常，不得虚构客户端列表或在线状态。

### 8.2 节点或数据缺失

不得仅因普通身份、进度或描述数据缺失，就推断客户端离线或异常。成功查询并确认对应 `alive` 临时节点不存在时，应判定为离线；只有因查询失败、连接异常、读取未完成或路径无法可靠解析而不能确认 `alive` 节点是否存在时，才展示未知或读取异常，不得虚构状态。

### 8.3 数据格式异常

当 ZK 节点数据无法按预期格式解析时，应标记该节点读取异常，不得静默丢弃或使用错误默认值。

### 8.4 部分失败

当部分客户端或任务读取成功、部分失败时，应继续展示已成功读取的内容，同时提示存在部分失败。

### 8.5 空数据

监控路径下没有任何客户端节点时，应显示空状态，不等于系统异常。

## 9. 当前暂不固化的内容

以下内容在当前阶段**不视为正式需求**，后续经用户确认后方可固化：

- 页面布局（卡片排列、列数、响应式断点）；
- 组件最终形式（卡片、表格、树形结构）；
- 页面颜色、主题、视觉效果；
- 字段显示顺序和列宽；
- 图标选择；
- 最终菜单位置和菜单组结构；
- 最终路由路径；
- 自动刷新间隔默认值和可选值；
- 当前 API URL、请求参数和响应字段结构；
- 前端组件实现方式和状态管理方案；
- 后端类和方法的具体设计；
- 异常提示的具体文案；
- `alive` 临时节点的最终路径解析实现；
- ZooKeeper 查询异常和无法解析数据的具体技术处理方式；
- 在线、离线、未知和读取异常状态的最终页面呈现方式；
- 最终展示字段集合；
- 字段之间的 fallback 规则；
- 任何验收通过结论。
