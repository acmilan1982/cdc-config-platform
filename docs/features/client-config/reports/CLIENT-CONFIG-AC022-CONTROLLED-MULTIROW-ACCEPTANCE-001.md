## 7. 为什么 AC-022 仍为 `BLOCKED`（不判 `PASS`）

本轮已把此前“启用仅 1 条”的证据缺口补齐：在受控窗口内取得同一时点 **2 启用 / 14 停用**
的多行真实快照，并在该快照上重跑了完整的成功态变化腿（启用成功→标记消失→业务字段不变→
停用恢复），无需再依赖历史腿。

仍未 `PASS` 的唯一原因是**定义口径**而非证据：AC-022 前置写的是“启用与停用探针**各若干条**”，
项目中没有经负责人批准的“若干条”数量阈值。本任务提示词明确：

- “至少 2 条”仅是本次准备多行样本的**操作目标**，不得宣布为正式数量阈值；
- 若完整定义的数量意图仍无法判明，应如实报告并**保留待明确项**，**不强判 `PASS`**；
- 不得修改“若干条”文字，不得为交付强改状态。

因此本轮如实记录已取得的事实，把 AC-022 维持 `BLOCKED`，等待负责人对该前置数量口径的澄清。
这不是“样本不足”导致的 `BLOCKED`，也不是真实反例，故不判 `FAIL`。

AC-082 的异常状态样本缺口未受本任务影响，维持 `BLOCKED`；本任务未制造异常值，未改其状态。
