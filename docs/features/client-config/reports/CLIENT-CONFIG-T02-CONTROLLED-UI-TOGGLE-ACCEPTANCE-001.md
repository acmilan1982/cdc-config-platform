### 5.3 确认框关闭与写请求的时间关系（精确记录，含限制）

| 观察点 | B3 启用 | B6 停用 |
|---|---|---|
| 页面点击时刻（page clock） | `1793685561960` | `1793685566523` |
| 门禁拦截写请求 | `2026-11-03T05:59:21.962Z` | `2026-11-03T05:59:26.522Z` |
| 后端 SQL `UPDATE` | `13:59:21.998`（Updates: 1） | `13:59:26.535`（Updates: 1） |
| 弹窗 DOM 不再可见（MutationObserver `firstHiddenAt`） | `1793685562201`（≈请求后 239 ms） | `1793685566744`（≈请求后 222 ms） |
| 请求时弹窗快照 | wrapper `display=inline-block`、`visibility=visible`，处于离场过渡 | 同左 |

实现顺序（对运行中实际安装的 Element Plus 2.14.2 源码核对，摘录见证据 `element-plus-close-order.txt`；源文件 `frontend/node_modules/element-plus/es/components/message-box/src/index.vue_vue_type_script_lang.mjs` 与 `.../src/messageBox.mjs`）：`handleAction` → `doClose()` 同步置 `visible=false` → `nextTick` 发出 `action` → Promise resolve → 调用 `enableClient/disableClient`。因此**关闭状态转换在写请求之前**，写请求是在 `visible=false` 之后的下一个 tick 才发出；而 DOM 可见性/节点移除要等约 300 ms 的离场过渡结束，故请求与淡出动画重叠。

`ui-toggle-results.json` 中的 `close_before_request=false` 是按“DOM 不再可见”定义的布尔量，反映的正是上述过渡重叠，不表示请求先于关闭动作。运行中未观察到弹窗内加载/处理中按钮态；请求期间的自然忙碌体现在底层行菜单项 `is-disabled`。

本报告按 R1 可执行性说明判定：当前流程在点击后**先进入关闭状态、随后调用接口**，不存在需要延迟接口才能构造的“处理中主按钮”可观察阶段。上述过渡重叠照实记录，不以“DOM 已移除”冒充已完成；若审查口径要求 DOM 完全移除后才允许发请求，则本节构成明确限制。
