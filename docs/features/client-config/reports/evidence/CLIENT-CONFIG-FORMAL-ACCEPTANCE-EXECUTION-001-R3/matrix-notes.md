# R3 覆盖矩阵说明（脱敏）

## 判定标准与边界

- 判定标准：`ACCEPTANCE.md` §4 **现行定义（含定向修订）**。对每个 R2 后仍为 `PASS` 的用例，把定义拆成关键 **PRE**（前置条件）、**STEP**（操作/输入）、**EXP**（预期结果）三类检查点，逐点判定。
- 判定词汇：
  - `COVERED`：原始证据中存在执行**本用例当前定义所要求的具体条件**的记录；
  - `MISSING`：原始证据中不存在该步骤的执行记录（含"仅有静态属性/公式外推而无实测"）；
  - `SIMULATED_ONLY`：该步骤仅由受控模拟（`simulated:true`）覆盖，不足以支撑要求**真实后端/真实写入**的步骤。
- 一个用例只有在**全部现行关键步骤**均为 `COVERED` 时，整条才维持 `PASS`；交叉借用其它用例的证据时，须能证明它执行了本条要求的具体条件。
- 步骤拆分与覆盖判定为**人工逐条审核**结果；生成脚本 `build-coverage-matrix.py` 仅做组织与渲染，**不**将 `v:PASS`、`all:true`、`hasNoOverflow:true` 等结果布尔值自动视为定义全覆盖。

## 视口证据的结构性事实（轴 C 的依据）

- 全包 `acc*.json` 的 `meta.viewport`：除 `accJ.json` 为 `1440x900 / 1920x1080`、`accH.json` 为 `variable` 外，其余全部为 **`1440x900` 单腿**。
- 实际执行过 **1920×1080** 观测的仅有：`accJ.json` 各键、`accI.json#016`（`at1440`/`at1920`）、`accH.json#126`（`measurements` 含 1920）。
- 仅存在的 1920 截图：`I-016-capability-1920.png` 一张。
- 因此，凡现行 STEP 明确要求"在 1440×900 与 1920×1080 两种视口下观察……"、而该用例又不属于上述 `016/126/accJ` 集合者，其 **1920 腿无原始记录**，只能判定该步骤 `MISSING`。本轮据此下调的 15 条均属此类（部分用例在轴 C 之外还叠加了轴 B/D 的缺口，见下）。

## 逐条要点（补充矩阵）

- `013`（轴 B）：`013-part@accC` 取到的是**机构名可取**时的冲突 Tooltip；全包无"机构名缺失→回退原始数据源 ID"的样例（`106@accC` 的 `orgMissingItems=0`、`accH` 备注"机构名缺失分行在当前数据集不可构造"）。R2 已因同一分支不可构造下调 `106`；保留 `013` 与 `106` 判定自相矛盾。
- `098`（轴 C + 前置数据）：`098@accG` 仅命中 `≥7` 一类（`total=7` 一条），**恰好 6 个**样本未出现；STEP 的三条视口腿（1440/1920/缩窄）未齐。不得以公式推算代替实测。
- `100`（轴 C + D）：`100-trigger@accD` 仅记 `allIcon`/`ariaOk`/`sampleAria`；既无 1920 腿，也未逐一覆盖"每一行"，更无 Tab 键盘聚焦动作与可见焦点样式/截图。仅 ARIA 名称不足以证明焦点可见。
- `128`（轴 A + C）：`128-limit@accE` 仅记录**粘贴** 40→32；无**手工连续键入 >32 位**的记录（`129` 的 `maxlength` 为静态属性观察）。`128-illegal@accE` 仅记 `ab cd` 与前端错误；全包无"重复/大小写不同 ID 触发真实后端唯一性校验"的记录，前端错误与代码推断不能替代要求真实后端的步骤。
- `101`（轴 D）：STEP 明确要求悬停/焦点反馈与键盘遍历菜单，原始证据（`accD`）无 `hover` 相关字段，也无键盘遍历记录。
- `017/079`（轴 C + 断言冲突）：除 1920 腿缺失外，`079` 的"新增按钮右对齐"断言在 `acc-result.json` 记为 `FAIL`（`addRightAligned=false`），与 `accA` 的 `PASS` 冲突，且未在原始证据内消除。
- `136`（轴 C）：STEP 要求桌面与**窄视口**、新增与编辑两模式；`136@accE` 仅桌面一腿且模式未标注，无窄视口记录。

## 保留 `PASS` 的说明性残余（不影响本步 `COVERED`）

以下用例维持 `PASS`，但矩阵中已注明观察边界，供复审判断：

- `012`：Tooltip 出现延迟（约 200~300ms）未单独计时；超长机构名样例未逐一列出，仅以 120px 上限体现截断规则。
- `041`：证据为单次状态快照，未做时序多次采样（定义未要求）。
- `046`/`129`：原始 `acc*` 中出现 `PARTIAL` 记录；经核对，缺失子项不属于该用例当前定义要求的真实后端/写入步骤，故其关键步骤仍 `COVERED`。
- `142`/`149`：`accB.json` 中曾记 `FAIL`，已由 `accB2.json` 的补跑结果取代（同一条件重跑通过），非产品反例。
- `144`：其失败分支为受控注入（`simulated:true`、`injectedFailure`），对应定义本就要求"前端如何呈现失败"，故记为 `COVERED` 并标注 `SIMULATED_ONLY` 边界。

## 环境与数据限制（非产品缺陷）

- 轴 B/部分轴 C 的缺失源于**原始执行时数据集中不存在**相应夹具（恰好 6 个数据源、机构名缺失行、窄视口/1920 腿等），属**环境与数据限制**，不据此判为 `FAIL`。
- 本任务为**只读复核**：不构造数据、不运行测试/构建/浏览器、不访问数据库/ZooKeeper/Kafka、不放行任何非 GET 业务请求，也不点击任何启停/删除最终确认。故上述缺失步骤在本轮**不会被补测**。
