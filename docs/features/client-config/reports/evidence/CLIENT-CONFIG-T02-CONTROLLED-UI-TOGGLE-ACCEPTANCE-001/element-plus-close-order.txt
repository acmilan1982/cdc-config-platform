Element Plus close-order source excerpt (installed 2.14.2)
=========================================================

Why this excerpt exists
-----------------------
The runtime close observer shows the dialog DOM becoming non-visible about
220–240 ms AFTER the write request, because the leave transition runs while the
request is in flight. To make the ordering auditable from the committed evidence
(node_modules is not versioned), the exact installed `doClose`/`handleAction`/
`onAction` code is recorded here. No file was modified.

Order derived from the installed code
-------------------------------------
click -> handleAction('confirm') -> doClose():
    visible.value = false            (synchronous, before any request)
    nextTick(emit('action'))
        -> options.onAction -> currentMsg.resolve(...)
            -> page's `await ElMessageBox.confirm(...)` resumes
                -> enableClient()/disableClient()  (write request)

Therefore the close state transition precedes the write request. The dialog's
DOM/visibility teardown is governed by the leave transition
(`--el-transition-duration`, default 0.3 s) and completes after the request.
This is the exact overlap recorded in ui-toggle-results.json
(B3/B6 `close_before_request=false`, `close_observer.firstHiddenAt`).
