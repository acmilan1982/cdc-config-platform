## 2. Feature 定位与术语

### 2.1 Feature 定位

“探针端管理”属于 CDC 配置管理平台的配置面，负责维护 Oracle 表 `CDC_CLIENT_MULTIPLE`。每个 `sync-client` 进程都有一个 `client_id`；进程启动或读取配置时，用自身 `client_id` 在 `CDC_CLIENT_MULTIPLE` 中查找 `CLIENT_ID` 相同且 `FG_ACTIVE=1` 的记录，再从该记录的 `DATA_SOURCE_ID` 读取需要采集的数据源。本 Feature 负责对上述探针配置记录做新增、编辑、启用、停用与删除维护。

### 2.2 术语

| 术语 | 说明 |
|---|---|
| 探针 / 探针端 | 一个采集进程（`sync-client`）的配置主体，对应 `CDC_CLIENT_MULTIPLE` 的一行记录；用户可见名称为“探针端管理”，历史文档/旧页面可能称为“客户端配置”。 |
| 探针 ID | 主键 `CLIENT_ID`，`VARCHAR2(32)`，同一探针的稳定标识。 |
| 探针描述 | `CLIENT_DESC`；项目负责人确认数据库已由原 `VARCHAR2(256)` 扩展为 `VARCHAR2(1024)`，且经正式复审在真实数据库查询元数据确认物理语义为 `VARCHAR2(1024 BYTE)`（`CHAR_USED=B`）；本 Feature 需求与验收统一按去除首尾空白后非空、UTF-8 编码字节数不超过 1024 的 BYTE 语义编写。 |
| 采集数据源 | `DATA_SOURCE_ID`，无转义、无引号的英文逗号分隔协议，弱逻辑引用 `CDC_DATA_SOURCE` 中记录，无物理外键。 |
| 规范化数据源 ID | 对 `DATA_SOURCE_ID` 做“按英文逗号拆分、每项去除首尾空白、忽略空项”后得到的非空 ID token；唯一分配、计数、去重判断均基于规范化后的 token。 |
| 状态 | `FG_ACTIVE`：`1` 表示启用、`0` 表示停用；非 `0/1` 值为历史异常状态。 |
| 有效探针配置 | `FG_ACTIVE = '1'` 的探针记录，是 `sync-client` 按 `client_id` 能命中的配置。 |
| 停用 | 把记录 `FG_ACTIVE` 更新为 `0`，使对应 `sync-client` 无法按活跃配置命中该记录。 |
| 数据源候选 | 新增/编辑“采集数据源”时可选择的来源：`CDC_DATA_SOURCE` 中 `FG_ACTIVE=1` 且 `DATA_SOURCE_CATEGORY=SOURCE`（大小写不敏感）且 `DATA_SOURCE_TYPE=ORACLE`（大小写不敏感）的记录。 |
| 异常数据源 | 已选数据源中处于停用、在 `CDC_DATA_SOURCE` 中不存在、ID 含英文逗号、或与另一探针重复分配等历史异常状态的数据源。 |
| 生效边界 | 本 Feature 只维护数据库配置记录，不直接启停、重启或通知 `sync-client`，不操作 ZooKeeper、Kafka、Topic 或运行进程；页面不得承诺配置对运行中进程立即生效。 |

## 6. 统一解析与序列化约定（本 Feature 多值弱逻辑引用基础规则）

`DATA_SOURCE_ID` 是无转义、无引号、无长度前缀的英文逗号分隔协议。读取（展示、计数、去重、唯一分配校验、查询匹配）统一按以下规则解析，避免不同功能各自解释造成口径分裂：

- 按单个英文逗号（`,`）拆分；
- 对每个拆分项执行去除首尾空白（Trim）；
- 忽略拆分后为空的项；
- 空字符串、仅含空白与仅含空项序列，解析结果为“无数据源”。

写入（新增/编辑保存）时统一按以下规则序列化：对用户最终选定的数据源 ID，去除首尾空白、忽略空项、按规范化结果去重、保持用户选择顺序，以单个英文逗号连接且不在逗号前后增加任何空格。

> 上述协议中，去重、顺序、异常标记与同一行历史重复 ID 的具体展示/计数口径，分别落实为 §7.2、§7.5、§7.7、§7.8 的对应需求；协议本身不新增数量上限。

| CCFG-REQ-017 | 数据源为停用、在 `CDC_DATA_SOURCE` 不存在、ID 含英文逗号或与其他探针重复分配等历史异常时，必须用红色异常标签展示；异常标签必须优先进入可见的标签（单行可见集），在满足异常优先的前提下其余数据源保持既有原始保存顺序。 |
| CCFG-REQ-018 | “数据源数量”列必须按解析后的非空数据源 ID 项计数（对同一行历史重复 ID 按 Trim 后不同 ID 去重计数，去重口径见 CCFG-REQ-019）。 |
| CCFG-REQ-019 | 同一行历史重复数据源 ID 的展示与计数必须统一：按 Trim 后不同 ID 去重展示和计数，同时把原配置含重复 ID 标记为异常；不得为展示与计数制造两个不同口径；后续设计阶段必须与该去重口径保持一致。 |

### 7.5 新增与编辑表单

| 编号 | 规则 |
|---|---|
| CCFG-REQ-036 | 新增与编辑表单字段必须为三项：探针 ID、探针描述、采集数据源；不得增加其他业务字段。 |
| CCFG-REQ-037 | 探针 ID：必填；去除首尾空白后长度必须为 1～32 字符；格式必须满足 `^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`。 |
| CCFG-REQ-038 | 探针 ID 去除首尾空白后，在普通顺序新增/编辑及当次写前检查的目标规则下，必须在全部 `CDC_CLIENT_MULTIPLE.CLIENT_ID` 中按 ASCII 大小写不敏感比较保持唯一：当次检查能够看到既有冲突时必须拒绝保存，`probe-001`、`Probe-001`、`PROBE-001` 必须视为同一个唯一键，不能属于三条不同记录。因 CCFG-REQ-037 已限定探针 ID 只能由英文字母、数字、句点、下划线与连字符组成，大小写折叠只涉及英文字母，不引入中文或区域化大小写规则。保存时必须保留用户最终输入的大小写形式，不得强制转大写或转小写。新增时当次检查只要看到已存在仅大小写不同的探针 ID，必须拒绝保存并提示冲突。编辑时以“原探针 ID”排除当前记录后再校验：当前记录仅调整自身 ID 大小写（如 `probe-001` 改为 `PROBE-001`）且无其他冲突记录时允许保存并保留新大小写，相当于当前记录自身的大小写调整；当次检查看到另一条与目标 ID 仅大小写不同的记录时必须拒绝。前端可提前校验，但后端保存前必须执行最终校验，不得因下述并发例外弱化普通操作或绕过前端直接调用时的后端检查。并发语义：本规则属于写入前应用校验规则，只约束普通顺序新增/编辑及当次写前检查；不通过 Oracle 显式表锁把校验与写入串行化。极端并发竞态是明确例外：当次检查通过后、写入完成前另一请求可能已先写入，两个请求可能先后都成功并产生仅大小写不同的多条记录；配置平台不再承诺并发下“最多一个成功”，这种并发结果作为已接受并发边界（见 CCFG-REQ-077），不属于本 Feature 验收失败。Oracle 主键只保证数据库自身的精确值唯一，不得把它当作已提供不区分大小写唯一的物理约束；本规则是本 Feature 的应用层目标业务约束，不得新增函数索引、约束或执行任何 DDL。 |
| CCFG-REQ-039 | 探针描述：必填；去除首尾空白后必须非空。最终保存值按 Oracle 数据库字符集 AL32UTF8 对应的 UTF-8 编码计算，字节长度不得超过 1024，即物理容量 `CLIENT_DESC = VARCHAR2(1024 BYTE)`。限制对象是编码后的字节数，不是 Java `String.length()`、JavaScript 字符数、Unicode 码点数或页面肉眼字符数：纯 ASCII 1024 个字符为 1024 字节可以通过，纯 ASCII 1025 个字符必须拒绝；常用中文在 AL32UTF8 下通常占 3 字节，即使字符数远小于 1024，只要 UTF-8 字节数超过 1024 也必须拒绝；Emoji 等补充字符通常占 4 字节，必须按真实 UTF-8 编码长度计数，不得按 Java UTF-16 code unit 或 JavaScript `.length` 误判。前端提示与预校验、后端最终校验必须使用同一 UTF-8 字节口径，后端必须作为最终防线；具体公共字节计算工具与测试方式留待设计阶段，本需求只固定口径。 |
| CCFG-REQ-040 | 采集数据源：必填，至少选择 1 个；不设置数量硬上限；序列化结果不得超过 `DATA_SOURCE_ID` 的 `VARCHAR2(1000)` 物理容量。 |
| CCFG-REQ-041 | 新增保存时 `FG_ACTIVE` 必须固定写入 `1`；新增表单不得提供状态字段。 |
| CCFG-REQ-042 | **【本轮定向修订 · 待批准】** 编辑弹窗同样不得提供状态字段，编辑弹窗不得包含启停控件；启用/停用只能从列表最右侧固定“操作”列“更多”下拉操作（原“从列表状态列操作”由本轮 `CCFG-REQ-095/096` 取代）。 |
| CCFG-REQ-043 | 新增保存前必须按 CCFG-REQ-038 的不区分大小写唯一语义校验探针 ID；只要已存在精确相同或仅大小写不同的记录，必须拒绝保存并提示冲突。 |
| CCFG-REQ-044 | 编辑弹窗打开时，探针 ID 默认必须只读并显示锁定状态。 |
| CCFG-REQ-045 | 仅当用户点击明确入口“修改探针 ID”后才解除探针 ID 只读；不得弹出“修改前警告”框。 |
| CCFG-REQ-046 | 探针 ID 解锁后，原入口必须变为“取消修改”；点击“取消修改”必须恢复原探针 ID 并恢复只读状态。 |
| CCFG-REQ-047 | 修改探针 ID 时不得检查、修改或级联处理其他表、其他进程、ZooKeeper 或 Kafka 的关联。 |
| CCFG-REQ-048 | 更新主键时必须以“原探针 ID”定位当前记录并排除之，再以“新探针 ID”执行格式校验（CCFG-REQ-037）与不区分大小写唯一性校验（CCFG-REQ-038）；当前记录仅调整自身 ID 大小写且无其他冲突记录时允许保存并保留新大小写，改成与另一条记录仅大小写不同的 ID 时必须拒绝。 |
| CCFG-REQ-049 | 编辑保存必须整体成功或整体失败，不允许探针 ID、探针描述与采集数据源仅部分保存。 |
| CCFG-REQ-050 | “探针描述”输入框右侧必须提供“自动生成”按钮，且按钮始终保持可点击状态，不得因未选择数据源、编辑历史记录或其他表单状态而显示为禁用。 |
| CCFG-REQ-051 | “自动生成”必须是一次性文本填充工具，不代表表单模式，不得保存或提交任何“描述生成模式”，不得新增数据库字段。 |
| CCFG-REQ-052 | 点击“自动生成”时先检查“采集数据源”是否存在已选项；未选择任何数据源时，必须什么都不做：不清空探针描述、不修改探针描述、不弹确认、不显示错误，也不改变任何表单状态。 |
| CCFG-REQ-053 | 存在已选数据源时点击“自动生成”，不得弹二次确认，必须直接清空探针描述当前内容，再按当前“采集数据源”的选择顺序读取每个数据源的 `DATA_SOURCE_ORG`，使用单个英文逗号连接并写入输入框，逗号前后不得增加空格。 |
| CCFG-REQ-054 | 自动生成时不得按机构名称排序，不得因机构名称相同而去重；每个已选数据源必须对应一个 `DATA_SOURCE_ORG` 片段。 |
| CCFG-REQ-055 | 自动生成对每个 `DATA_SOURCE_ORG` 仅去除首尾空白，不得改变其内部字符、大小写或中文内容。 |
| CCFG-REQ-056 | 自动生成完成后，探针描述输入框必须立即恢复为普通可编辑文本，用户可继续增加、删除或修改任何文字。 |
| CCFG-REQ-057 | 自动生成之后继续增删采集数据源不得自动更新探针描述；用户需要时可再次点击“自动生成”重新覆盖。 |
| CCFG-REQ-058 | 新增与编辑表单必须都提供同一个“自动生成”按钮；打开编辑弹窗时只原样回显已保存的 `CLIENT_DESC`，不得自动判断、自动生成或自动覆盖。 |
| CCFG-REQ-059 | 提交时只提交最终 `CLIENT_DESC` 文本；后端必须继续执行必填、去除首尾空白与 `VARCHAR2(1024 BYTE)` 的 UTF-8 字节长度校验（口径同 CCFG-REQ-039），不得重新生成描述，不得比较其是否等于机构名称组合。 |
| CCFG-REQ-060 | “自动生成”拼接各 `DATA_SOURCE_ORG`（英文逗号连接的完整结果）同样受 `VARCHAR2(1024 BYTE)` 限制，必须按 UTF-8 编码字节数判断，不得只按字符数判断。若任一当前已选数据源无法取得非空 `DATA_SOURCE_ORG`（此时须明确指出对应数据源 ID），或完整生成结果去除首尾空白后为空、或按 UTF-8 编码字节数超过 1024，则自动生成必须失败并给出明确提示，保持原探针描述不变，不得静默截断；点击按钮前已有自定义内容会被覆盖，这是用户明确触发按钮的结果，不得再增加确认弹窗、撤销状态或“自定义/自动”切换控件。 |

### 7.7 一个源库原则上只分配给一个探针（目标规则、普通校验与并发边界）

| 编号 | 规则 |
|---|---|
| CCFG-REQ-068 | 一个规范化数据源 ID 原则上最多只能出现在一条 `CDC_CLIENT_MULTIPLE` 记录的 `DATA_SOURCE_ID` 中，这是配置平台目标业务规则与普通操作校验规则：在非并发的正常操作中，当写前检查能看到既有占用时必须拒绝新增重复分配；历史异常或极端并发仍可能使表内出现重复，页面必须识别并展示，不得宣称数据库物理保证（不强一致唯一约束、不显式表锁）。 |
| CCFG-REQ-069 | 唯一分配校验必须覆盖表中所有记录，包括 `FG_ACTIVE=0` 以及其他历史异常状态记录；停用不释放数据源。 |
| CCFG-REQ-070 | 只有从原记录中移除该数据源或删除原记录，该数据源才被释放。 |
| CCFG-REQ-071 | 新增与编辑保存时，后端必须在执行 DML 前重新读取 `CDC_CLIENT_MULTIPLE` 全部记录并校验全部拟保存数据源，不能只依赖前端禁选；该检查是尽力写前检查，不通过 Oracle 显式表锁把检查与写入串行化。 |
| CCFG-REQ-072 | 启用时后端必须在更新 `FG_ACTIVE='1'` 前执行与新增/编辑相同的重复分配检查（写前重新读取并校验全部拟占用数据源），防止历史异常记录绕过新增/编辑规则；该检查同样是不取 Oracle 显式表锁的写前检查。 |
| CCFG-REQ-073 | 编辑排除当前记录时必须使用原探针 ID；修改后的新探针 ID 不得被误当作排除键。 |
| CCFG-REQ-074 | 当次写前检查发现任一数据源冲突、或当前请求自身执行失败时，整次保存或启用必须失败，不得部分写入；不得从该“整体失败”推导为并发下的全局唯一保证。 |
| CCFG-REQ-075 | 冲突错误信息必须至少包含机构名称（可解析时）、数据源 ID 与冲突探针 ID，例如：数据源“中心医院（ds_oracle_011）”已分配给探针 probe-hosp-007，不能重复分配。 |
| CCFG-REQ-076 | 若异常历史数据已被多个探针占用，错误信息必须列出全部冲突探针 ID，不得任意隐藏其中一个。 |
| CCFG-REQ-077 | 并发边界与运行侧防线：① 新增、编辑、启用不为数据源唯一分配执行 Oracle 显式表锁；② 探针 ID 大小写不敏感唯一性校验（CCFG-REQ-038）同样不依赖显式表锁；③ 每个请求仍须在 DML 前执行当次后端检查（见 CCFG-REQ-071/072）；④ 接受检查与写入之间存在竞态窗口、极端并发下两个请求先后都写入成功的可能；⑤ 配置平台不再在并发下提供“最多一个成功”的强保证，两笔都在竞态窗口中成功不作为本 Feature 验收失败；⑥ 不新增唯一约束、函数索引、触发器、关联表、锁表或任何 DDL；⑦ `sync-client`、`sync-server` 在使用配置时会执行数据源重复分配检查，作为运行侧最终防线，但不属本 Feature 实现、调用、通知或验收模拟范围。 |
