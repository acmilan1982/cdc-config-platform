## 2. Feature 定位与术语

### 2.1 Feature 定位

“探针端管理”属于 CDC 配置管理平台的配置面，负责维护 Oracle 表 `CDC_CLIENT_MULTIPLE`。每个 `sync-client` 进程都有一个 `client_id`；进程启动或读取配置时，用自身 `client_id` 在 `CDC_CLIENT_MULTIPLE` 中查找 `CLIENT_ID` 相同且 `FG_ACTIVE=1` 的记录，再从该记录的 `DATA_SOURCE_ID` 读取需要采集的数据源。本 Feature 负责对上述探针配置记录做新增、编辑、启用、停用与删除维护。

### 2.2 术语

| 术语 | 说明 |
|---|---|
| 探针 / 探针端 | 一个采集进程（`sync-client`）的配置主体，对应 `CDC_CLIENT_MULTIPLE` 的一行记录；用户可见名称为“探针端管理”，历史文档/旧页面可能称为“客户端配置”。 |
| 探针 ID | 主键 `CLIENT_ID`，`VARCHAR2(32)`，同一探针的稳定标识。 |
| 探针描述 | `CLIENT_DESC`；项目负责人确认数据库已由原 `VARCHAR2(256)` 扩展为 `VARCHAR2(1024)`，且经正式复审在真实数据库查询元数据确认物理语义为 `VARCHAR2(1024 BYTE)`（`CHAR_USED=B`）；本 Feature 需求与验收统一按去除首尾空白后非空、UTF-8 编码字节数不超过 1024 的 BYTE 语义编写。 |
| 采集数据源 | `DATA_SOURCE_ID`，无转义、无引号的英文逗号分隔协议，弱逻辑引用 `CDC_DATA_SOURCE` 中记录，无物理外键。 |
| 规范化数据源 ID | 对 `DATA_SOURCE_ID` 做“按英文逗号拆分、每项去除首尾空白、忽略空项”后得到的非空 ID token；唯一分配、计数、去重判断均基于规范化后的 token。 |
| 状态 | `FG_ACTIVE`：`1` 表示启用、`0` 表示停用；非 `0/1` 值为历史异常状态。 |
| 有效探针配置 | `FG_ACTIVE = '1'` 的探针记录，是 `sync-client` 按 `client_id` 能命中的配置。 |
| 停用 | 把记录 `FG_ACTIVE` 更新为 `0`，使对应 `sync-client` 无法按活跃配置命中该记录。 |
| 数据源候选 | 新增/编辑“采集数据源”时可选择的来源：`CDC_DATA_SOURCE` 中 `FG_ACTIVE=1` 且 `DATA_SOURCE_CATEGORY=SOURCE`（大小写不敏感）且 `DATA_SOURCE_TYPE=ORACLE`（大小写不敏感）的记录。 |
| 异常数据源 | 已选数据源中处于停用、在 `CDC_DATA_SOURCE` 中不存在、ID 含英文逗号、或与另一探针重复分配等历史异常状态的数据源。 |
| 生效边界 | 本 Feature 只维护数据库配置记录，不直接启停、重启或通知 `sync-client`，不操作 ZooKeeper、Kafka、Topic 或运行进程；页面不得承诺配置对运行中进程立即生效。 |

## 6. 统一解析与序列化约定（本 Feature 多值弱逻辑引用基础规则）

`DATA_SOURCE_ID` 是无转义、无引号、无长度前缀的英文逗号分隔协议。读取（展示、计数、去重、唯一分配校验、查询匹配）统一按以下规则解析，避免不同功能各自解释造成口径分裂：

- 按单个英文逗号（`,`）拆分；
- 对每个拆分项执行去除首尾空白（Trim）；
- 忽略拆分后为空的项；
- 空字符串、仅含空白与仅含空项序列，解析结果为“无数据源”。

写入（新增/编辑保存）时统一按以下规则序列化：对用户最终选定的数据源 ID，去除首尾空白、忽略空项、按规范化结果去重、保持用户选择顺序，以单个英文逗号连接且不在逗号前后增加任何空格。

> 上述协议中，去重、顺序、异常标记与同一行历史重复 ID 的具体展示/计数口径，分别落实为 §7.2、§7.5、§7.7、§7.8 的对应需求；协议本身不新增数量上限。

### 7.5 新增与编辑表单

| 编号 | 规则 |
|---|---|
| CCFG-REQ-036 | 新增与编辑表单字段必须为三项：探针 ID、探针描述、采集数据源；不得增加其他业务字段。 |
| CCFG-REQ-037 | 探针 ID：必填；去除首尾空白后长度必须为 1～32 字符；格式必须满足 `^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`。 **【本轮（第四轮）定向修订 · 待批准】** 本条原文与判定规则（首字符、允许字符、判空、长度 1～32、大小写不敏感唯一性与后端校验）全部保留不变；本轮在其上**追加输入层口径**：输入与粘贴最多接受 32 位（超长不再无限录入），非法字符**不得**被静默改写成另一个 ID，必须以字段级错误明确指出格式问题。定向修订与新增编号见 §7.13 `CCFG-REQ-131`。 |
| CCFG-REQ-038 | 探针 ID 去除首尾空白后，在普通顺序新增/编辑及当次写前检查的目标规则下，必须在全部 `CDC_CLIENT_MULTIPLE.CLIENT_ID` 中按 ASCII 大小写不敏感比较保持唯一：当次检查能够看到既有冲突时必须拒绝保存，`probe-001`、`Probe-001`、`PROBE-001` 必须视为同一个唯一键，不能属于三条不同记录。因 CCFG-REQ-037 已限定探针 ID 只能由英文字母、数字、句点、下划线与连字符组成，大小写折叠只涉及英文字母，不引入中文或区域化大小写规则。保存时必须保留用户最终输入的大小写形式，不得强制转大写或转小写。新增时当次检查只要看到已存在仅大小写不同的探针 ID，必须拒绝保存并提示冲突。编辑时以“原探针 ID”排除当前记录后再校验：当前记录仅调整自身 ID 大小写（如 `probe-001` 改为 `PROBE-001`）且无其他冲突记录时允许保存并保留新大小写，相当于当前记录自身的大小写调整；当次检查看到另一条与目标 ID 仅大小写不同的记录时必须拒绝。前端可提前校验，但后端保存前必须执行最终校验，不得因下述并发例外弱化普通操作或绕过前端直接调用时的后端检查。并发语义：本规则属于写入前应用校验规则，只约束普通顺序新增/编辑及当次写前检查；不通过 Oracle 显式表锁把校验与写入串行化。极端并发竞态是明确例外：当次检查通过后、写入完成前另一请求可能已先写入，两个请求可能先后都成功并产生仅大小写不同的多条记录；配置平台不再承诺并发下“最多一个成功”，这种并发结果作为已接受并发边界（见 CCFG-REQ-077），不属于本 Feature 验收失败。Oracle 主键只保证数据库自身的精确值唯一，不得把它当作已提供不区分大小写唯一的物理约束；本规则是本 Feature 的应用层目标业务约束，不得新增函数索引、约束或执行任何 DDL。 |
| CCFG-REQ-039 | 探针描述：必填；去除首尾空白后必须非空。最终保存值按 Oracle 数据库字符集 AL32UTF8 对应的 UTF-8 编码计算，字节长度不得超过 1024，即物理容量 `CLIENT_DESC = VARCHAR2(1024 BYTE)`。限制对象是编码后的字节数，不是 Java `String.length()`、JavaScript 字符数、Unicode 码点数或页面肉眼字符数：纯 ASCII 1024 个字符为 1024 字节可以通过，纯 ASCII 1025 个字符必须拒绝；常用中文在 AL32UTF8 下通常占 3 字节，即使字符数远小于 1024，只要 UTF-8 字节数超过 1024 也必须拒绝；Emoji 等补充字符通常占 4 字节，必须按真实 UTF-8 编码长度计数，不得按 Java UTF-16 code unit 或 JavaScript `.length` 误判。前端提示与预校验、后端最终校验必须使用同一 UTF-8 字节口径，后端必须作为最终防线；具体公共字节计算工具与测试方式留待设计阶段，本需求只固定口径。 **【本轮（第四轮）定向修订 · 待批准】** 本条原文与判定口径（Trim 仅判空、最终描述原文保存、`VARCHAR2(1024 BYTE)` 的 UTF-8 字节 ≤1024、后端为最终防线）全部保留不变；本轮在其上**追加界面输入层上限**：探针描述输入与粘贴最多 256 个字符（按 Unicode 完整字符计数），输入提示改为“最多 256 个字符”，`1024 BYTE` 的数据库／API／服务端上限**不**随之改为 256 字节。定向修订与新增编号见 §7.13 `CCFG-REQ-132`。 |
