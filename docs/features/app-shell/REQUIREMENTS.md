# 全局应用外壳现代化视觉主题 — 需求基线

功能目录：`app-shell`
任务编号：`APP-SHELL-VISUAL-BASELINE-CLOSEOUT-001`
文档职责：本文件描述**已确认的目标需求**，并记录当前实现与验收状态。需求正文与设计令牌（第 10 节）为权威口径；当前实现事实见本功能 `README.md`。

---

## 1. 调整背景

当前 CDC 配置管理平台的全局应用外壳（左侧菜单、顶部栏、页面容器与公共视觉主题）沿用早期技术选型的默认配色，存在以下问题：

- 侧栏使用较旧的灰蓝色（`#304156`），整体观感陈旧；
- 菜单选中态仅通过文字变色（`#409eff`）表达，层级与选中状态不够清晰；
- 页面背景、内容卡片与公共组件的视觉语言不统一，缺乏现代企业后台的层次感。

因此需要对全局应用外壳和公共视觉主题进行一次**仅限视觉表现**的现代化升级，不改动任何业务功能与信息架构。

---

## 2. 调整目标

在**信息架构保持不变**的前提下，对全局应用外壳和公共视觉主题进行现代化升级，整体采用已经通过视觉确认的第一版方向：

> 现代深海军蓝侧栏 + 克制科技蓝强调色 + 浅灰蓝页面背景 + 白色内容卡片。

整体气质要求：

- 专业、稳重、现代、清晰；
- 适合配置管理、数据管理和运行监控系统；
- 不做炫酷大屏式、霓虹式或科幻式设计。

---

## 3. 适用范围

本需求覆盖以下全局应用外壳与公共视觉主题相关的界面对象：

- 全局应用主布局（`MainLayout`）；
- 左侧菜单（含 Logo 区、菜单分组、菜单项、图标）；
- 顶部栏与面包屑；
- 页面容器与内容卡片；
- 全局 CSS、CSS Variables / 主题变量；
- Element Plus 全局样式覆盖；
- 公共组件的一致视觉状态（默认、悬停、选中、聚焦、禁用、加载、空数据、错误）。

---

## 4. 明确非范围

本需求**不**涉及以下内容：

- 任何后端接口、数据库对象、表结构或业务数据口径的变更；
- 任何菜单分组、层级、顺序、名称的调整；
- 任何路由地址的调整；
- 任何页面业务结构、页面功能的调整；
- 任何权限规则的调整；
- 任何数据来源或数据口径的调整；
- “数据同步统计大屏”页面内部的业务布局与视觉设计（本需求不调整大屏页面自身）；
- 修改“数据同步统计大屏”菜单的打开行为（改为新浏览器标签页打开）——该目标为已确认的后续需求，本轮不实现；
- 任何与本任务无关的新功能（搜索、消息、用户中心等）。

2. 菜单层级；
3. 菜单顺序；
4. 菜单名称；
5. 路由地址；
6. 页面业务结构；
7. 页面功能；

### 5.1 “数据同步统计大屏”的平级定位与打开方式

“数据同步统计大屏”是“运行监控”分组下的一个普通监控功能，与“CDC 节点状态”“数据源运行状态”“Topic 偏移量”“日志查询”“故障监控”等功能**完全平级**。

**平级指菜单层面的一致待遇**，具体包括菜单分组、层级、尺寸、字体、图标规格、普通状态、悬停状态和入口待遇一致。

必须满足：

- 不为“数据同步统计大屏”设置特殊菜单颜色；
- 不设置特殊尺寸、独立分组或特殊装饰；
- 不使用区别于其他菜单项的选中规则；
- 在渲染全局应用外壳和左侧菜单的普通管理页面中，只有当前访问的菜单项显示统一选中态。

**独立全屏模式（当前实现，本轮保持不变）**：

- 当前 `/large-screen` 保持 `standalone` 独立全屏页面定位；
- 独立全屏页面不渲染 `MainLayout`，因此不显示左侧菜单和顶部栏；
- 大屏全屏页面中不要求展示左侧菜单选中态；
- 大屏不显示侧栏，不等于其菜单入口具有特殊层级或特殊视觉待遇；
- 普通应用外壳页面继续遵守统一的菜单选中态规则；
- 本次视觉主题调整不修改大屏页面内部的业务布局和视觉设计。

**已确认的后续需求 / 本次延期实施项**：

> 用户在管理平台点击“数据同步统计大屏”菜单后，在新的浏览器标签页中打开 `/large-screen`；新标签页直接进入 standalone 独立全屏页面，不显示 `MainLayout`、左侧菜单和顶部栏；原管理平台页面保持打开。

该目标为**已确认的后续需求**，处理边界如下：

- 本次 `APP-SHELL-THEME-REQ-001-R1` 不实现；
- 随后的视觉主题代码开发任务也不实现；
- 不纳入本轮视觉主题开发的验收标准；
- 后续应通过独立任务修改菜单打开行为并单独验收；
- 本轮保持当前路由地址和当前打开行为不变。

不得把未来新标签页行为写成当前已经实现的事实。

## 6. 左侧菜单视觉与交互规则

左侧菜单是本次视觉升级的重点，采用**深海军蓝侧栏**方向。

### 6.1 目标色值（左侧菜单）

| 对象 | 目标颜色 |
|---|---|
| 侧栏主背景 | `#0F172A` |
| Logo 区背景 | `#111C30` |
| 菜单分组文字 | `#94A3B8` |
| 普通菜单文字 | `#CBD5E1` |
| 菜单悬停背景 | `#1E293B` |
| 当前菜单背景 | `#1D4ED8` |
| 当前菜单文字 | `#FFFFFF` |
| 当前菜单左侧强调线 | `#60A5FA` |

> 说明：菜单分组文字在深色侧栏（`#0F172A`）上以约 `12px` 小字号展示，`#94A3B8` 相比 `#64748B` 可读性更好，同时仍保持弱于可点击菜单文字的层级；普通菜单文字继续使用 `#CBD5E1`，页面次要文字 `#64748B` 保持不变，本次仅调整深色侧栏上的菜单分组文字。

### 6.2 交互与层级要求

- 可点击菜单项使用统一的行高、内边距、缩进和圆角；
- 菜单项建议形成约 `44px` 的稳定垂直节奏，最终值可结合当前布局实现，但各菜单必须一致；
- 每个可点击菜单项使用风格统一、尺寸一致的简洁线性图标；
- 分组标题应小于且弱于可点击菜单文字，形成明确层级；
- 普通、悬停、当前选中、键盘聚焦状态必须能够清楚区分；
- 当前菜单使用蓝色圆角选中块、白色文字和左侧细强调线；
- 不允许只通过文字变蓝表示当前菜单；
- 图标和文字必须对齐；
- 左侧侧栏固定为 `220px` 展开宽度，不提供整体折叠/展开能力；
- Logo 区显示名称以第 16 节“界面显示名称”的目标为准，并保持清晰可读；可使用与现有技术栈兼容的简洁几何标识，但不得引入复杂品牌重设计。

### 6.3 侧栏固定展开与菜单分组规则

- 普通应用外壳页面的左侧侧栏固定宽度为 `220px`，不提供整体折叠/展开能力；
- 顶部栏不设置侧栏折叠/展开按钮；
- Logo 区完整名称始终显示；
- 菜单图标与菜单文字始终同时显示；
- 菜单分组标题始终显示；
- 主内容区和顶部栏始终按固定 `220px` 侧栏宽度布局；
- 不保存、不恢复、不切换任何侧栏折叠状态；
- “配置管理”“运行监控”为静态分组标题，不可点击、不提供展开/收起或手风琴交互；
- 两个分组的下级菜单始终展示，不维护分组展开状态，分组标题旁不显示展开/收起控件；
- standalone 大屏 `/large-screen` 不渲染 `MainLayout` 和左侧侧栏，固定 `220px` 规则不适用于大屏页面。

### 8.2 布局与层级要求

- 公共内容卡片建议使用约 `8px` 圆角；

- 减少大面积纯白背景带来的空旷感，但不得虚构内容填充页面；
- 页面标题、辅助文字、筛选栏、表格和按钮应形成稳定的字号与间距层级；
- 主按钮采用克制的科技蓝，不使用荧光蓝、霓虹光或强烈渐变。

## 11. 可用性与兼容性要求

- 中文文字必须清晰可读；
- 文字与背景保持足够对比度；
