## 2. 验收设计目的、适用范围与非目标

### 2.1 目的

- 本文档把已批准 `REQUIREMENTS.md`、`API.md`、`DESIGN.md` 与本次 `UI.md` 的可验收规则转化为可直接指导开发自测、联调、接口测试与人工验收的详细用例，供用户复审与后续执行。
- 每个用例明确前置条件、操作步骤、预期结果、证据类型与建议执行层级，验收结论可复核、可追溯。
- 验收用例只覆盖上游设计允许的行为；上游明确禁止的行为（见 §2.3）不设用例或只设"不得出现"的反向校验用例。

### 2.2 适用范围

- 覆盖 §6.2 列出的 30 个验收领域；
- 性能验收按 §8 明确分层：A（代码开发阶段可执行）/ B（菜单开放前必须执行）。

### 2.3 非目标与禁止行为

以下行为不提供正向用例，且对应反向校验用例（如无特殊标注）必须确认其不发生（来源 `LQ-NONGOAL-01~20`、`LQ-LOAD-01 / 33`、`LQ-PAGE-04 / 05 / 06`、`LQ-DETAIL-22 / 27`、`LQ-API-10`、`LQ-DB-14`）：

1. 自动刷新、轮询、WebSocket、自动重试；
2. 导出、删除、修改、重试、忽略、提醒等写操作入口；
3. 总数、页码跳转、任意 `pageSize`、传统 OFFSET 分页；
4. 用户点击表头排序；
5. 模糊表名查询、自动大小写转换、表名自动补全或缓存候选；
6. 无时间范围查询、清空时间范围后查询；
7. 列表预取完整 `LOG_DETAIL`、`RAW_MESSAGE` 或 `RESULT_DETAIL`；
8. 抽屉替代已确认的弹窗；
9. 未经批准的新查询条件或统计卡片；
10. `RESULT_DETAIL` 展示；
11. 查询状态跨页面持久化（LocalStorage / SessionStorage）；
12. 解除菜单隐藏限制（最终物理设计与生产等价性能验收完成前）。

## 3. 验收结果状态模型

| 状态 | 含义 | 说明 |
|---|---|---|
| `NOT_RUN` | 尚未执行 | 所有新建用例的初始状态；执行前不得改为 PASS/FAIL |
| `PASS` | 已执行且符合预期 | 必须附证据（截图 / 接口记录 / 构建日志 / 测试报告 / 性能报告） |
| `FAIL` | 已执行且不符合预期 | 必须记录失败点、复现步骤与证据 |
| `BLOCKED` | 受环境或依赖阻塞 | 必须记录阻塞原因与恢复条件 |
| `DEFERRED_UNTIL_PHYSICAL_DESIGN` | 必须在最终物理设计完成后执行 | 仅用于依赖最终分区/索引/生产 DDL/生产等价性能环境的用例（见 §8 性能分层 B） |

规则：

- 本文档所有用例初始状态为 `NOT_RUN`；物理设计相关用例初始状态为 `DEFERRED_UNTIL_PHYSICAL_DESIGN`。
- 不允许把"验收设计完成"写成"功能验收通过"；不允许把开发库验证结果外推为生产性能结论。
- 执行状态记录必须标注执行人、执行日期与证据位置；本文档不预留伪造状态的空间。

## 5. 验收领域范围

本文档覆盖以下 30 个验收领域（编号即 §6.2 顺序）：

1. 页面入口、双 Tab 顺序、默认 Tab 与首次查询；
2. 两 Tab 独立状态及重新进入菜单的状态失效；
3. 查询条件、默认值、必填校验、精确匹配、多选与"全部"；
4. 当前自然日的计算时点、跨午夜不自动推进；
5. 最大 7 天排他边界公式，包括恰好 7 天合法和多 1 秒拒绝；
6. 表单条件与已生效条件分离；
7. 重置不查询、不清列表、不改游标；
8. 固定排序、固定 100 条、101 条探测、无总数、无跳页；
9. 请求游标栈的首页、下一页、连续三页、两次上一页、失败原子性；
10. 新增/晚到日志下不承诺跨请求快照一致性；
11. `CDC_LOG_ID` 超过 JavaScript 安全整数时仍以字符串无损传输；
12. 数据源候选、名称映射、停用/缺失/空值降级、禁止 N+1；
13. 列表 12 列、列顺序、横向滚动、固定列、单行省略和 Tooltip；
14. 四个时间字段全部显示且格式一致；
15. 日志摘要与完整详情隔离；
16. 原始消息按需加载且列表不预取；
17. 合法 JSON 的"原文/格式化"切换、复制必须复制原始内容；
18. 非 JSON、空内容、超长文本、超大 CLOB 的展示；
19. 纯文本安全展示，禁止把日志内容作为 HTML 执行；
20. 查询加载、3 秒慢提示、动态秒数、25/30 秒超时协调；
21. 失败、超时、游标失效、旧响应和跨 Tab 响应隔离；
22. 空数据与字段 NULL 的 `--` 规则；
23. 不自动刷新、不自动重试；
24. 权限与只读边界、非法 `logType`、SQL 注入防护；
25. 列表、详情、原始消息三条 SQL 路径的大字段隔离；
26. 页面支持的桌面分辨率、无页面与表格双重纵向滚动条；
27. 无障碍与键盘交互；
28. 菜单隐藏、物理设计延期和正式开放前置条件；
29. 开发库功能验收与生产等价性能验收的明确分层；
30. 回归范围与构建、测试、截图、接口证据要求。

> 执行说明：菜单开放前（含代码开发与开发库联调阶段），可通过浏览器直接访问路由 `/monitor/log-query` 进行页面自测；左侧菜单按钮必须保持隐藏（领域 28）。涉及"进入菜单"的用例在开发阶段验证到"菜单隐藏 + 路由可访问"即可，不得以开放菜单的方式通过。

## 6. 详细验收用例

> 每个用例包含：前置条件、操作步骤、预期结果、证据类型、建议执行层级、初始状态。编号从 `LQ-AC-001` 起，唯一且不悬空。

### 6.1 领域 1：页面入口、双 Tab 顺序、默认 Tab 与首次查询

#### LQ-AC-001 单菜单与路由
- 前置条件：功能代码已实现并可在开发库运行；页面可通过路由访问（开发阶段菜单保持隐藏）。
- 操作步骤：1. 登录平台，检查左侧菜单；2. 访问 `/monitor/log-query`。
- 预期结果：仅一个"日志查询"菜单，未新增第二个"日志观察"菜单；路由 `/monitor/log-query` 页面不再显示占位内容，展示真实日志查询页面。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-002 双 Tab 顺序与默认 Tab
- 前置条件：同上。
- 操作步骤：进入页面，观察 Tab 区。
- 预期结果：两个 Tab，顺序为"错误日志"在前、"正确日志"在后；默认打开"错误日志"。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-003 首次进入自动查询错误日志第一页
- 前置条件：同上。
- 操作步骤：1. 重新进入页面；2. 观察请求网络记录与列表。
- 预期结果：首次进入即发起一次 `POST /api/log-query/logs/search`（`logType=error`，默认当前自然日），请求成功后列表展示第一页；请求失败则显示错误态（见领域 21）。
- 证据类型：接口证据、人工 UI 截图
- 建议执行层级：接口测试、人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-004 正确日志第一次切换才首次查询
- 前置条件：同上。
- 操作步骤：1. 进入页面，等待错误日志首查完成；2. 观察是否出现 `logType=correct` 请求；3. 首次切换到"正确日志"。
- 预期结果：首次进入后未出现 `logType=correct` 请求；切换到"正确日志"时才发起其首次查询；正确日志首次查询前不创建其列表与游标状态。
- 证据类型：接口证据、人工 UI 截图
- 建议执行层级：接口测试、人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-005 Tab 与数据源表映射
- 前置条件：开发库 `CDC_LOG_ERROR`、`CDC_LOG_CORRECT` 有数据。
- 操作步骤：分别在两个 Tab 查询并核对网络请求 `logType`。
- 预期结果：错误日志 Tab 请求 `logType=error`；正确日志 Tab 请求 `logType=correct`；服务端映射到 `CDC_LOG_ERROR` / `CDC_LOG_CORRECT`，返回对应表数据。
- 证据类型：接口证据、接口自动化测试
- 建议执行层级：接口测试
- 初始状态：NOT_RUN

#### LQ-AC-006 Tab 标题不显示总数
- 前置条件：进入页面。
- 操作步骤：观察 Tab 标题与页面任何区域。
- 预期结果：Tab 标题仅显示"错误日志""正确日志"，页面不展示全量总数、不展示总记录数。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-007 无写操作入口
- 前置条件：进入页面。
- 操作步骤：检查列表行、表格工具栏、弹窗与页面全部可操作控件。
- 预期结果：不存在新增、修改、删除、导出、重试、忽略、提醒等任何写操作入口；页面只提供查询、翻页、查看详情/原始消息、复制。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-008 页面标题与说明
- 前置条件：进入页面。
- 操作步骤：观察页面顶部。
- 预期结果：页面标题显示"日志查询"，标题下有一行简短说明（只读检索同步日志、错误日志/正确日志双 Tab、按固定排序游标分页）。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

### 6.2 领域 2：两 Tab 独立状态及重新进入菜单的状态失效

#### LQ-AC-011 两 Tab 状态完全独立
- 前置条件：进入页面。
- 操作步骤：1. 错误日志查询并翻页；2. 切换正确日志查询并翻页；3. 来回切换观察各 Tab 表单、列表、分页、游标。
- 预期结果：两个 Tab 的表单条件、已生效条件、列表、请求游标栈、`hasNext`/`nextCursor`、加载状态、错误状态、初始化标志各自独立，互不覆盖；来回切换不发起新查询，直接恢复各自状态。
- 证据类型：人工 UI 截图、接口证据
- 建议执行层级：人工 UI、接口测试
- 初始状态：NOT_RUN

#### LQ-AC-012 切换 Tab 不销毁不重建
- 前置条件：两个 Tab 均已至少查询过一次。
- 操作步骤：1. 错误日志翻到第 2 页；2. 切换正确日志再切回错误日志。
- 预期结果：错误日志仍显示第 2 页、原已生效条件与原游标栈；切换过程无新查询请求。
- 证据类型：人工 UI 截图、接口证据
- 建议执行层级：人工 UI、接口测试
- 初始状态：NOT_RUN

#### LQ-AC-013 一个 Tab 的操作不影响另一个 Tab
- 前置条件：两个 Tab 均已有列表。
- 操作步骤：在错误日志点击查询/重置/翻页，观察正确日志状态；反之亦然。
- 预期结果：正确日志的表单、列表、游标、加载状态完全不变；错误日志响应不得写入正确日志状态。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-014 后台查询 Tab 的独立加载标识
- 前置条件：通过造数使列表查询耗时超过约 1 秒（或接口测试层验证逻辑）。
- 操作步骤：1. 在错误日志发起慢查询；2. 切换正确日志。
- 预期结果：错误日志 Tab 标题旁显示小型加载标识，正确日志可正常操作；两 Tab 加载状态相互独立。
- 证据类型：人工 UI 截图
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-015 重新进入清除状态恢复默认
- 前置条件：两个 Tab 均已做过修改表单、查询、翻页操作。
- 操作步骤：分别以三种方式重新进入：浏览器刷新；离开后从其他菜单返回；再次点击左侧"日志查询"菜单（即使当前已在该路由）。
- 预期结果：三种方式均清除两个 Tab 全部临时状态与游标，恢复默认表单（时间=重新进入时所在自然日），默认打开错误日志并自动查询第一页。
- 证据类型：人工 UI 截图、接口证据
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-016 重新进入后正确日志等待切换再查询
- 前置条件：进入页面完成错误日志首查。
- 操作步骤：重新进入页面后观察网络请求。
- 预期结果：重新进入后仅错误日志自动首查，正确日志不发起查询，直到第一次切换才查询。
- 证据类型：接口证据
- 建议执行层级：接口测试
- 初始状态：NOT_RUN

#### LQ-AC-017 不持久化查询状态
- 前置条件：进入页面并修改表单、翻页。
- 操作步骤：1. 检查浏览器 LocalStorage / SessionStorage；2. 刷新后观察。
- 预期结果：查询状态不写入任何浏览器持久化存储；刷新后状态清空并恢复默认。
- 证据类型：人工 UI（浏览器存储面板截图）
- 建议执行层级：人工 UI
- 初始状态：NOT_RUN

#### LQ-AC-018 重新进入后旧响应被丢弃
- 前置条件：接口测试环境；能制造"旧请求慢返回"场景。
- 操作步骤：1. 发起慢查询 A 后立即重新进入页面；2. 慢查询 A 的响应在重新进入后返回。
- 预期结果：旧请求尽量被取消；无法取消时通过页面代次/请求令牌失效；旧响应返回不得覆盖新页面的表单、列表、游标、加载与错误状态。
- 证据类型：接口证据、接口自动化测试
- 建议执行层级：接口测试
- 初始状态：NOT_RUN

#### LQ-AC-019 跨 Tab 响应隔离
- 前置条件：能制造"错误日志请求慢、正确日志请求快"场景。

## 8. 性能验收分层

> 性能验收必须与物理设计延期保持严格边界：开发阶段可执行的形态检查与开发库功能验证 ≠ 生产性能结论。菜单开放以 B 层全部通过为前提（`LQ-DB-14`、`LQ-PERF-09~13`）。

### A. 代码开发阶段可以执行

| 用例 | 验收内容 | 结论边界 |
|---|---|---|
| LQ-AC-159 | SQL 形态检查：必带 `TARGET_TIME`、无 `OFFSET`、无 `COUNT(*)`、无日志大表与数据源表大范围 JOIN | 只证明 SQL 形态正确，不构成性能结论 |
| LQ-AC-160 | 固定 101 条读取上限 | 同上 |
| LQ-AC-161 | 列表不预取完整大字段 | 同上 |
| LQ-AC-162 | 超时配置、取消和失败恢复 | 验证配置与行为 |
| LQ-AC-163 | 开发库接口响应与功能正确性 | 不以开发库当前查询速度推断生产性能（`LQ-PERF-14`） |
| LQ-AC-077 / 146 | 数据源单次读取、无 N+1、无大表 JOIN | 可结合可获得的执行计划或 SQL 证据记录风险，不外推为生产性能结论 |

### B. 菜单开放前必须执行（受最终物理设计延期约束）

| 用例 | 验收内容 | 前置条件 |
|---|---|---|
| LQ-AC-156 | 最终一级 RANGE 分区粒度确定 | 40 个数据源完成首次全量、取得 `TARGET_TIME` 真实分布 |
| LQ-AC-157 | 是否使用子分区、最终索引列序及本地/全局形态确定、生产 DDL 完成 | 同上 |
| LQ-AC-158 | 完全离线调整窗口执行 | 分区与索引调整 DDL 已批准 |
| LQ-AC-164 | 首页 ≤3 秒 | 生产等价数据规模、值域、分布与并发条件 |
| LQ-AC-165 | 下一页 ≤2 秒 | 同上 |
| LQ-AC-155 | 全部阻断指标通过后才允许解除菜单隐藏 | B 层全部用例通过并批准 |

- 上述 B 层用例初始状态一律为 `DEFERRED_UNTIL_PHYSICAL_DESIGN`，不得写成通过或失败。
- 若 B 层性能不达标，按 `LQ-PERF-12` 停止并报告 SQL、执行计划、扫描量、索引或分区缺口；不允许为通过验收而删除查询条件、缩小需求范围或静默修改指标（`LQ-PERF-13`）。
