## 2. Feature 定位与术语

### 2.1 Feature 定位

“数据同步进度”属于 CDC 配置管理平台“运行监控”模块，是一个**绝对只读**的数据同步断点进度查询页面。页面读取 `sync-server` 持久化到数据库的消费断点（`CDC_TOPIC_OFFSET` 表达的业务数据，本平台只读），展示每个 Kafka 业务 Topic 在中心端（`SERVER_ID`）下的已保存消费位置与断点更新时间。

第一版**只查询数据库断点，不连接 Kafka**；不判断断点是否过期、异常、离线或有效；不展示完成百分比；不提供任何写动作。通过 Kafka 才能得到的末端位置、待消费数量、消费延迟三项，第一版统一显示“—”。

### 2.2 术语

| 术语 | 说明 |
|---|---|
| 数据同步进度 | 页面与菜单的正式名称；内部 Feature 目录标识继续使用 `topic-offset`，路由保持 `/monitor/topic-offset`。 |
| sync-client | CDC 同步客户端进程，从源库读取数据并写入 Kafka 业务 Topic。通常有多个。 |
| sync-server | CDC 同步服务端进程，消费所有业务 Topic 并将数据同步到目标库。中心端 `sync-server` 进程只有一个。 |
| 中心端 | 以 `SERVER_ID` 标识的 sync-server 部署单元。列表中“中心端”列原样展示 `SERVER_ID`。 |
| Kafka Topic（业务 Topic） | 一个源表 + 一个目标库对应一个 Kafka Topic；每个 Topic 有且只有一个分区。 |
| 断点 / 已保存消费位置 | `NEXT_OFFSET`：sync-server 定期把每个 Topic 的下一消费位置写入 `CDC_TOPIC_OFFSET`，作为重启续传断点。`NEXT_OFFSET` 仅表示“下一条准备消费的消息位置”，而且是定期持久化值，不等同于进程内存中的绝对实时位置。 |
| Kafka 末端位置 | Kafka 分区的下一写入位置（第一版不接入 Kafka，无实际值）。 |

| 同步对象 | 由 `KAFKA_TOPIC` 按“客户端.源库.Schema.表名.目标库”五段解析后用于展示的组合（两行：客户端/源库/目标库一行、Schema.表名一行）。 |

| 无法解析 Topic | 按英文句点拆分为不等于 5 段的 `KAFKA_TOPIC`；不得猜测、部分解析或从配置反向推断。 |

## 3. 业务背景与数据来源

1. `sync-client` 从源库读取数据并写入 Kafka 业务 Topic。
2. 一个源表 + 一个目标库对应一个 Kafka Topic。
3. `sync-client` 通常有多个；中心端 `sync-server` 进程只有一个。
4. `sync-server` 消费所有业务 Topic，将数据同步到目标库。
5. 每个 Topic 有且只有一个分区。
6. `sync-server` 定期把每个 Topic 的下一消费位置写入 `CDC_TOPIC_OFFSET`，作为重启续传断点。
7. `NEXT_OFFSET` 仅表示“下一条准备消费的消息位置”，而且是定期持久化值，不等同于进程内存中的绝对实时位置。
8. 数据量规模（用户确认的规模假设）：开发环境约十余条记录；生产环境通常不超过 6000 条。
9. 本平台对 `CDC_TOPIC_OFFSET` 表达的数据绝对只读。

## 5. 功能范围（范围内/范围外）

### 5.1 范围内

- 通过左侧“运行监控”菜单进入“数据同步进度”页，读取数据库断点并展示同步进度列表；
- 固定 8 列表格：序号、同步对象、已保存消费位置、Kafka 末端位置、待消费数量、消费延迟、断点更新时间、中心端；
- 查询区四个条件：客户端｜源库｜目标库｜表名（前三者为多选下拉并含“全部”特殊选项）；
- Topic 原值权威保留与严格五段解析展示；
- 客户端、源库、目标库下拉候选读取全部配置并按规则映射名称与停用/缺失状态；
- 固定每页 150 条的分页、`KAFKA_TOPIC ASC, SERVER_ID ASC` 固定排序、60 秒自动刷新与立即刷新；
- 首次进入自动缺省查询、同一会话返回页面恢复已生效查询现场；
- 断点字段按字符串精确保留与展示；Kafka 三列第一版显示“—”。

### 5.2 范围外

- 连接 Kafka 或读取任何 Kafka 实时指标；

- 对 `CDC_TOPIC_OFFSET` 的任何写入、清理或修复；
- 修改现有菜单、路由或占位页面（本任务不改动任何前后端文件）；
- 创建 DESIGN.md / API.md / UI.md / DATABASE.md；
- 访问 Oracle、Kafka、ZooKeeper/TongZK；执行任何 SQL、DDL、DML；
