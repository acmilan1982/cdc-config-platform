## 2. 页面信息架构（自上而下固定，TOFF-REQ-117）

```
┌────────────────────────────────────────────────────────────┐
│ 数据同步进度                                    [页面标题]  │
│ ⓘ Kafka 实时数据尚未接入。Kafka 末端位置、待消费数量和消费延迟暂不计算。 [Kafka提示，TOFF-REQ-067] │
│ ┌ 查询区（单行）：客户端▾  源库▾  目标库▾  表名[____]  [查询][重置] ┐ │
│ ┌ 工具栏：共 N 条 · 无法解析 M 条 | 60秒自动刷新·最近成功刷新 HH:mm:ss [立即刷新] ┐ │
│ ┌ 8列表格（fixed-left: 序号、同步对象；其余横向滚动）           ┐ │
│ └ 分页：共 N 条，第 x/共 p 页  [上一页/下一页…]（固定150/页）      ┘ │
└────────────────────────────────────────────────────────────┘
```

- 不提供统计卡片、图表、导出按钮、行操作、完成百分比、复选框（TOFF-REQ-007/008/071/119）。
- “同步对象”为视觉主列；四个进度字段为核心信息组；更新时间和中心端为断点信息组（TOFF-REQ-120）。

## 3. 查询区（TOFF-REQ-021/022/023/024/025/026/027/030/034/035/036/037/040~053）

- 四个条件一行布局：客户端、源库、目标库（多选下拉，均含特殊选项“全部”）、表名（文本输入）。无其他查询条件（TOFF-REQ-021/022）。
- “全部”固定为下拉第一项（TOFF-REQ-050），用哨兵值 `__ALL__` 仅在表单层表示，不传给后端（TOFF-REQ-023）。
- 互斥语义：默认选中“全部”；选择具体项自动取消“全部”；点击“全部”清空具体项；清空具体项后恢复“全部”（TOFF-REQ-024/025）。
- 候选项：
  - 客户端标签 `ID（描述）`；描述为空只显示 `ID`；描述过长省略并悬浮展示完整描述（TOFF-REQ-041/047）。
  - 源库/目标库标签 `ORG（ID）`；`ORG` 为空显示“未定义名称（ID）”（TOFF-REQ-042/043/048）。
  - 停用项保留，标签附“已停用”标记（TOFF-REQ-045/046）。
  - 候选来源全部配置，不从实际 Topic 提取（TOFF-REQ-040）；每次查询/刷新读取最新（TOFF-REQ-052）。
  - 已生效筛选 ID 刷新期间被删除：不清除，选项区临时显示“ID（配置不存在）”，清除/重置后消失（TOFF-REQ-053/051）。
- 按钮：
  - 查询：提交草稿→回到第 1 页（TOFF-REQ-035/091）。
  - 重置：表单恢复三个“全部”+空表名；**不立即查询**（TOFF-REQ-037）。
- 草稿与列表分离：修改条件但未点“查询”，列表不变化（TOFF-REQ-036/039）；表名输入在提交前去首尾空格（TOFF-REQ-030）。

## 4. 工具栏（TOFF-REQ-020/092/103/104/105/107/108/114）

固定顺序：结果总数、无法解析数量、60 秒刷新状态、最近成功刷新时间、立即刷新（TOFF-REQ-117）。

| 元素 | 规则 |
|---|---|
| 结果总数 | `共 {total} 条`（过滤后全集，TOFF-REQ-092） |
| 无法解析数量 | `无法解析 {unparseableTotal} 条`；为完整查询结果的无法解析总数，非当前页（TOFF-REQ-020、TOFF-AC-018） |
| 60 秒刷新状态 | 常显“60 秒自动刷新”（可含状态点/转圈），自动刷新进行中不过度闪烁（TOFF-REQ-112） |
| 最近成功刷新时间 | `最近成功刷新 {HH:mm:ss}`：页面成功取得数据的本地时刻，非数据库 `UPDATED_AT`（TOFF-REQ-114、TOFF-AC-098） |
| 立即刷新 | 按钮；按已生效条件+当前页轻量刷新；成功后重计 60s（TOFF-REQ-104/108/110） |
| 刷新失败 | 自动刷新失败不弹堆叠提示，工具栏内联弱提示（TOFF-REQ-113）；保留原数据（TOFF-REQ-111） |

## 5. 表格 8 列与列宽（TOFF-REQ-081/094/095/096）

固定 8 列，顺序与建议宽度（§13 建议约束，UI 基线）：

| # | 列 | 建议宽度 | 对齐 | 说明 |
|---|---|---|---:|---|---|
| 1 | 序号 | 70px | 居中 | `fixed="left"`；跨页连续 (page−1)×150+行内行号（TOFF-REQ-082） |
| 2 | 同步对象 | min 380px | 左对齐 | `fixed="left"`；视觉主列，两行内容（§6） |
| 3 | 已保存消费位置 | 160px | 右对齐 | 值为 `NEXT_OFFSET`（TOFF-REQ-065）；等宽数字、无千分位（TOFF-REQ-077、TOFF-REQ-079、TOFF-REQ-080） |
| 4 | Kafka 末端位置 | 160px | 右对齐 | 显示 `—`（TOFF-REQ-066） |
| 5 | 待消费数量 | 140px | 右对齐 | 显示 `—` |
| 6 | 消费延迟 | 140px | 右对齐 | 显示 `—` |
| 7 | 断点更新时间 | 170px | 居中 | 单行 `YYYY-MM-DD HH:mm:ss`（TOFF-REQ-084/096） |
| 8 | 中心端 | 150px | 左对齐 | 原样展示 `SERVER_ID`（TOFF-REQ-085） |

- 序号与同步对象固定在左侧（TOFF-REQ-094）；空间不足时横向滚动，不把列压缩到不可读（TOFF-REQ-095）。
- 无任何表头排序/排序箭头（TOFF-REQ-086）；无分页规格选择器（TOFF-REQ-089）。
- 表格固定为上述 8 列，不单独增加状态列（TOFF-REQ-072）。
- 表格 `size="small" border`，沿用项目既有表格惯例。
- Kafka 三列（Kafka 末端位置/待消费数量/消费延迟）对应接口字段 `kafkaEndOffset/pendingCount/consumeLag`，前端类型为 `string\|null`；值为 `null` 时该单元格显示 `—`。渲染分支**只把 `null` 映射为 `—`**，绝不转成 `0` 或字符串 `"null"`（TOFF-REQ-066；与 API.md §3.1 的 JSON `null` 显式规则一致）。

## 6. 同步对象单元格

### 6.1 可解析（TOFF-REQ-054/055/056/057/058/059/060/061）

固定两行：

```
第一行：客户端ID → 源库ORG → 目标库ORG       （各段 + 状态标记）
第二行：Schema.表名
```

- 第一行客户端段只显示 ID，不显示描述（TOFF-REQ-055）。
- 源库/目标库段显示 `DATA_SOURCE_ORG`（TOFF-REQ-056）；`ORG` 为空显示“未定义名称”（TOFF-REQ-059）。
- 状态标记（第二段用小标记）：
  - 配置存在且启用：不显示标记。
  - 配置存在但停用：名称或 ID 后标记“已停用”（TOFF-REQ-057）。
  - 配置不存在：显示 Topic 中的原始 ID 并标记“配置不存在”（TOFF-REQ-058）。
- 内容过长省略；单元格仍**严格保持两行**，不换为一行/三行（TOFF-REQ-060）。
- 悬浮整个单元格 → 展示完整原始 Topic（TOFF-REQ-061/018）。
- 第二行文本 `Schema.表名` 由解析结果拼接展示（仅展示，不写回，TOFF-REQ-013）。

### 6.2 无法解析（TOFF-REQ-017/018/019/062）

- 单元格第一行显示文本 `Topic 格式无法解析`（TOFF-REQ-017），不展示任何猜测出的客户端/源库/Schema/表名/目标库（TOFF-REQ-062）。
- Offset、断点更新时间、中心端等其余字段照常展示（TOFF-REQ-016）。
- 悬浮展示：完整原始 Topic（TOFF-REQ-018），并就近提示 `该 Topic 无法按“客户端.源库.Schema.表名.目标库”拆分，请人工核对 Topic 命名。`（TOFF-REQ-019、TOFF-AC-017）。

## 7. 分页（TOFF-REQ-089、TOFF-REQ-091、TOFF-REQ-092、TOFF-REQ-093、TOFF-REQ-075）

- 固定每页 150 条，无规格选择器；分页栏显示总记录数、当前页码/总页数（TOFF-REQ-092）。
- 查询后回到第 1 页；刷新保持当前页（TOFF-REQ-091/110）。
- 刷新后当前页超过新最后一页 → 跳到新最后一页；空结果回到第 1 页（TOFF-REQ-093）。

## 8. 刷新与生命周期交互

页面状态含：首次加载、查询、轻量刷新、失败、空结果（TOFF-REQ-115/116；DESIGN §7）。

| 场景 | 交互 |
|---|---|
| 首次进入 | 缺省条件自动查询（TOFF-REQ-034/097）；成功后开始 60s 计时（TOFF-REQ-105） |
| 点击查询 | loading 整表态；回到第 1 页 |
| 重置 | 只改草稿；不查询（TOFF-REQ-037） |
| 手工刷新 | 轻量态（不清表）；按生效条件+当前页 |
| 自动刷新 | 60s；轻量态；不清表、不闪烁（TOFF-REQ-103/112） |
| 页面隐藏 | 停止自动刷新（TOFF-REQ-106） |
| 重新可见 | 立即刷新一次并重计（TOFF-REQ-107） |
| 离开再返回 | 恢复上次生效条件与页码；先展示保留结果并立即刷新（TOFF-REQ-099/101） |
| 请求进行中 | 不重叠请求（TOFF-REQ-109） |
| 刷新失败 | 保留原列表（TOFF-REQ-111） |
| 连续自动刷新失败 | 不堆提示（TOFF-REQ-113） |

## 9. 加载、空、错误与配置异常状态

| 状态 | 表现 |
|---|---|
| 首次加载 | 列表区 loading；工具栏轻态 |
| 轻量刷新 | 不清表；仅工具栏“刷新中”/状态点（TOFF-REQ-112） |
| 查询空结果 | 列表空态文案 `暂无符合条件的数据`；不是接口错误（TOFF-REQ-116） |
| 首次加载失败 | 整区错误态 + “重新加载”按钮，可重试当前条件（TOFF-REQ-115） |
| 后续失败 | 保留上一次成功结果，不清空（TOFF-REQ-039/111） |
| 配置停用 | 候选与同步对象标记“已停用”（TOFF-REQ-046/057） |
| 配置不存在（行） | 同步对象标记“配置不存在”（TOFF-REQ-058） |
| 配置不存在（筛选项） | 查询区临时项“ID（配置不存在）”（TOFF-REQ-053） |
| 名称为空 | 下拉“未定义名称（ID）”、同步对象“未定义名称”（TOFF-REQ-048/059） |

## 10. 响应式与横向滚动

- 序号、同步对象 `fixed="left"`；中右列随可用宽度显示，必要时整表横向滚动（TOFF-REQ-094/095）。
- 窄窗口下列宽不压到不可读（建议同步对象保持可读最小宽度）。
- 时间保持单行（TOFF-REQ-096）；Offset 列建议右对齐等宽，便于纵向比对（TOFF-REQ-079/080）。

## 11. 可访问性与 Tooltip

- 长文本省略（单元格/候选标签）都提供悬浮完整内容：同步对象悬浮原始 Topic；客户端候选悬浮完整描述（TOFF-REQ-047/061/018）。
- Tooltip 文案使用需求原文，避免歧义（TOFF-REQ-019/067）。
- 状态通过“标记文字 + 颜色”双通道表达（不只靠颜色），停用/不存在/未定义名称均有明确文本（TOFF-REQ-046/057/058/059）。

## 12. 视觉令牌（引用与局部定义）

- 全局沿用 `src/styles/theme.css` 的 `--app-*` 与 EP `--el-color-*`；警示色用 `--el-color-warning`、错误用 `--el-color-danger`、成功绿用 `--el-color-success`（第一版不使用成功绿；未来“0（已追平）”弱绿仅属后续口径，TOFF-REQ-073、TOFF-REQ-074）。
- Offset 等宽数字：页面局部样式 `.toff-offset { font-variant-numeric: tabular-nums; text-align: right; white-space: nowrap; }`（EP 无现成 monospace 令牌）。
- 停用/不存在标记可用 `el-tag size="small" type="warning/info"`；错误/未定义提示用内联弱色文本。
